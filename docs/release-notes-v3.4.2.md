# Ncrust v3.4.2-gpl

## 先说清楚：这个闪退是我造成的

v3.4.1 我修波形形状时，在三泳道渲染路径里多写了一个延伸点，**越界了**。**一播放就闪退**，责任在我。
如果你已经装了 v3.4.1，请**尽快换成本版**。

## 两个错误叠在一起

### 错误一：越界写 ⇒ 崩溃

v3.4.1 为补「位置平移后右边缘露出的缺口」，写了：

```kotlin
heights[total] = heights[total - 1]
peaks[total]   = peaks[total - 1]      // ← 越界
```

三个数组的容量当时**不一致**（`total = barCount × 3 = 84`）：

| 数组 | 容量 | 需要 |
|---|---|---|
| `heights` / `tangents` | `pointCount` = 84 | 84 ✓ |
| **`peaks`** | **`barCount` = 28** | **84 ✗** |

⇒ `ArrayIndexOutOfBoundsException`。而且只在**三泳道 + 真的在出声**时才走到 ——
所以「冷启不崩」完全不能说明问题。

### 错误二：容量被静默夹掉（修完错误一才暴露）

```kotlin
val n = minOf(count, heights.size, tangents.size)
```

渲染函数**会把点数静默夹到数组容量**。所以即使把三个数组都改成 84、传 `count = 85`，
那个延伸点也**根本画不出来** —— 我会得到一个"看起来修好了、其实右边缘缺口还在"的版本。
正确容量是 `pointCount + 1`。

## 修法

1. **容量对齐**：新增 `geomCount = pointCount + 1`，三个几何数组一律取它；
   并在声明处写明「凡与 `heights` 同下标的数组，容量必须取 `geomCount`」。
2. **显式守卫**：延伸前检查三个数组都容得下；容不下就**不延伸**（少画最右一格，画面几乎无差别），
   绘制点数跟着走 —— **渲染层的失误绝不该升级成崩溃**。
