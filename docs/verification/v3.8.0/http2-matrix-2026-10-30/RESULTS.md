# HTTP/2 对照：第一轮结果与尚未完成的归因

本轮用户明确授权真机、真实登录态、只读取链对照，覆盖此前仅本地拦截的旧限制。执行设备PLC110，Android API37，进程UID10377与Arris一致；没有安装/覆盖应用，没有音频播放，没有改动全局代理/网络。原始脱敏事件见matrix.jsonl，统计见summary.json。时间戳为设备时间，不能直接与宿主当前时间混用；连接阶段耗时均使用elapsedRealtime。

## 固定条件

同一曲25841325、jymaster、同一登录态快照、同一份eapi加密参数与请求头，所有请求串行、间隔2秒。OkHttp4.12.0、Okio3.9.1、Kotlin1.9.24；15秒PING、30秒空闲池、8秒整通截止、30秒连接/读取阶段超时，自动连接恢复沿用默认。每组3轮轮换顺序。只读POST，没有发送收藏/歌单/登录写操作。

独立app_process运行，没有载入应用UI/播放器；实际UID相同，但不等同应用进程内已有连接池或其生命周期。探针显式固定DIRECT和HTTP127.0.0.1:8888两条路由。使用系统CA加当前抓包CA，保留正常证书及主机名验证，无跳过TLS验证。

## 实测

| 条件 | 结果 | 阶段证据 |
|---|---|---|
| 直连，全新h2池，3次 | 2次8秒超时，1次200且可播，5450ms | 失败停在TCP；成功协商h2，TCP约5.15s、TLS约146ms |
| 直连，计划复用h2池，3次 | 2次8秒超时，1次200且可播，310ms | 前面未建成连接，第三次实际上仍是新连接id2，不能冒称三次均复用 |
| 直连，全新h1池，3次 | 全部约8002ms超时 | 均未进入TLS，尚未协商h1，不是已建立h1后的业务拒绝 |
| 直连，成功h2连接闲置约22秒后 | 200、可播，85ms | id2、reused=true，确认真正复用成功 |
| 直连，随后闲置35秒 | 200、可播，302ms | 新连接id3、reused=false，30秒空闲回收生效 |
| 显式抓包代理，12次含种子/空闲检测 | 全部2–4ms ECONNREFUSED | 尚未TLS；代理端口不可达，不能作为h1/h2差异样本 |

合计24次只读取链：直连12次（8次TCP阶段超时、4次h2成功可播），代理12次连接拒绝；另1条setup记录。没有重现之前的REFUSED_STREAM/CANCEL。因此本轮**不能宣称已查清原先拒流根因**，也不能据此宣布h1优于h2。

## 可以确认的结论

1. 本轮反复8秒超时发生在HTTP协商前；直接归咎HTTP/2不成立，独立h1也没有避开这些TCP失败。
2. 同一会话和参数随后得到4次可播h2响应，说明这批请求的会话/签名并非始终被拒绝。
3. 至少一次真实复用h2成功，且闲置回收符合30秒配置；不能把“所有复用都会坏”当成事实。
4. 环境准备时全局代理先为127.0.0.1:8888，并有adb reverse映射/宿主mitmdump；稍后全局代理变成:0，代理组实测连接拒绝。环境发生变化是观察事实，但未捕获改变时点/操作者，不能声称历史拒流一定来自代理。
