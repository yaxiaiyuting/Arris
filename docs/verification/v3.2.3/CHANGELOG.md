# Ncrust v3.2.3-gpl 更新说明（用户可读）

> 这一版是对 v3.2.2 的**两处实测反馈**的响应：
> ① 默认档（简洁档）看不到频带信息；② 刷新率低。
> **v3.2.2 的 tag 已经推上去了**，按本仓库纪律不移动它 —— 所以走新版本号
> （与 v2.1.1/v2.1.2 折进 v2.1.3 是同一处置）。

## 1. 刷新率（本次的主修）

先说结论：**同样 30 秒里，波形区渲染的帧数从 1227 涨到 1784（+45%，约 41fps → 59.5fps）**。

低刷新有**两个独立原因**，都不是"画得慢"：

1. **形状每 100ms 整条跳一格**：音频数据是每 100ms 一块（真机实测），而波形画的是历史窗口，
   以前是"来一块跳一格"。柱子的高度有平滑在抹，但**三条泳道的形状没有** ——
   所以哪怕帧率拉满，看到的仍是 10 Hz 的阶跃。
   **修法**：在相邻两格之间做**亚格插值**，形状按帧率连续左移（插的是"两格之间"，不是"未来"，
   没有编造数据）。
2. **S6 这类老系统被一刀切钉在 30fps**：原来的判据是"系统版本 < Android 8 或内存不足 ⇒ 33ms"。
   实测这台设备本来跑得动 ~50fps，那条上限纯属判据自己加的。
   **修法**：判据只保留"内存真的不足"这一条（`isLowRamDevice`），老系统不再降帧。

代价如实说：设备在同样时间里多画 45% 的帧，**单帧延迟涨了 3~4ms**（p95 从 29ms 到 32ms），
这是"吞吐换延迟"的取舍，而你要的正是更高的刷新率。

「不空转」的老规矩没破：静音 / 放完 / 暂停时既不为滚动排帧、也不推进相位。

## 2. 三条频带泳道（v3.2.2 已有，本版把默认档也打开）

波形按横轴分成三块，每块画**它自己那个频段**的时间曲线：

```
 左：低频（鼓 / 贝斯）   中：中频（人声 / 吉他）   右：高频（镲片 / 齿音）
```

- 三块**各自滚动**，但**首尾无缝拼接**成一条连续曲线；
- 接缝处**渐变过渡**，每块在自己的区间里是纯色；
- **不把三个频段的差别抹平**（左边高度只由低频决定、右边只由高频决定），
  每条泳道另有**显示增益标定**（低 2.6 / 中 3.5 / 高 6.6），否则高频永远是一条贴中线的直线；
- 三档**都**画三条泳道（v3.2.2 只在高档位开，低端机默认档看不到 —— 这是本次一起修的）。

颜色仍取主题色经 HCT 推导的三色组（实测三色感知色差 ΔE ≥ 10.1）。
"哪条泳道在主导，那条亮一点"的切换走完整的防闪（平滑 300ms + 滞回 20% + 100ms 过渡，
实测 0.103 次/秒、零闪断）。

## 3. 稳定性（与 v3.2.2 相同）

- 波形绘制失败只**丢这一帧**，不向上抛、不重试；
- 音频数据拿不到时**退回一条单色曲线**，不把"没测到"画成"是零"；
- 音频线程**没有新增任何逐样本计算**（三个频带本来就是既有产物）。

## 4. 未验证 / 已知限制

- **PCL110（Android 16）仍未验证**：本轮那台设备不在线。
- **老系统上 60fps 的发热与耗电**：本版把 S6 的帧间隔从 33ms 改成 16ms，
  只量了帧时间（+45% 帧数、p95 32ms），**没有测长跑功耗**。
  真觉得费电可以在设置里把动效强度降到「简洁」（那一档没有流光/粒子）。
