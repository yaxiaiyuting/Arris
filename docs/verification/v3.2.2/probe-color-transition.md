# 探针 §2.4 颜色切换方式（探针结论）

> 原始实测数据：[`probe/color-transition-measurements.md`](probe/color-transition-measurements.md)、
> 逐帧轨迹 [`probe/color-transition-trajectories.csv`](probe/color-transition-trajectories.csv)、
> 对照图 [`probe/color-transition-compare.png`](probe/color-transition-compare.png)、
> 三角色色板 [`probe/color-roles-swatches.png`](probe/color-roles-swatches.png)、
> 三色可区分性 [`probe/color-roles-measurements.md`](probe/color-roles-measurements.md)。

本探针比 §2.3 更进一步：测的是**生产类 `BandDominance` 本身**，而且按**生产时序**跑
（特征 11 Hz 到达 / 判定按 60fps 帧推进）—— §2.3 的扫描是在缓冲边界上判定的离线分析，
两者的差别必须实测而不是假设。

## 1. 三种方式的数值对照

指标：**相邻两帧混合色的 CAM16-UCS ΔE 最大值** —— 这就是「闪不闪」的数值形式：
硬切把一次切换的全部色差压进**一帧**，有过渡则摊到多帧。

| 方式 | 5 首合计切换次数 | 每帧最大色差 ΔE | 处于混合态的时间占比 |
|---|---|---|---|
| a. 硬切（过渡 0ms） | 128 | **17.58** | 0.0% |
| 过渡 40ms | 128 | 11.99 | 0.3% |
| 过渡 80ms | 128 | 8.13 | 0.7% |
| **c. 分段 + 短过渡 100ms（本版采用）** | 128 | **7.13** | 1.0% |
| 过渡 120ms | 128 | 6.44 | 1.2% |
| 过渡 400ms（= 线性渐变的最平滑形态） | 128 | 3.11 | 4.1% |

**切换次数在三种方式下完全相同（128）** ⇒ 过渡只改变"怎么过去"，不改变"什么时候换"，
防闪的责任仍在 §2.3 的平滑 + 滞回那一层。

## 2. 选型：分段 + 短过渡 **100ms**

- **硬切（a）明确不合格**：17.58 的色差在一帧里跳完，比 100ms 过渡跳 **2.5 倍**；
- **纯线性渐变（把过渡拉到 400ms）** 数值最好（3.11），但「混合态时间」从 1.0% 涨到 4.1%
  —— 有 4% 的时间画面上的颜色**既不是低频色也不是中频色**，"这一刻是哪个频带"这句话被稀释；
  任务书给出的推荐区间也正是 50~100ms；
- **100ms 是区间上沿、区间内色差最低**（40ms 11.99 / 80ms 8.13 / 100ms 7.13），
  混合态时间仍只有 1.0%，且**远小于实测最短驻留 300ms**（过渡总能在下一次切换前走完）。

## 3. 探针过程中**被实测否决**的两个想法（留档，避免下一个人重做）

### 3.1 用 smoothstep（ease-in-out）代替线性权重 —— **实测更差**

直觉：线性插值的第一步占了整段色差的 46%（80ms/60fps ⇒ 权重一步走 0.2，
CAM16-UCS 色差却跳了 8.13，而整段才 17.58），所以"压起步"应该能改善。
实测：`t' = t²(3−2t)` 之后 80ms 档的每帧最大色差从 **8.13 涨到 9.33**。
原因：smoothstep 的斜率峰值在 t=0.5（1.5×），而混色的**中段**恰好落在 CAM16 空间里
变化最快的区域 —— 缓动只是把峰值搬了个位置，起决定作用的是颜色本身。
⇒ 本版用**线性**权重，把"每帧色差"压下来的手段是**加长过渡**（上表）。

### 3.2 允许在过渡中途再次切换 —— **实测会制造 pop**

权重是 `previous·(1−t) + dominant·t`。如果过渡走到一半就把 `previous` 换成新的 dominant，
权重会从"混了一半的中间色"**瞬间跳回纯色**：实测那一次跳变的 ΔE 是 8.13。
修法：「**过渡期间不接受新切换**」（`transition >= 1f` 才允许），等价于最短驻留 = 过渡时长。
加上之后"过渡被打断"次数 **128 → 0**，代价为零（实测最短驻留 300ms ≫ 100ms）。

## 4. HCT 三角色映射（primary / secondary / tertiary）

三色的可区分性用 **CAM16-UCS ΔE** 与 **WCAG 对比度**两条判据量（判据写在测之前：
ΔE ≥ 5 必需、≥ 10 理想；对比度 ≥ 3.0）。种子是**真实主题色**：6 个预设 + 8 个封面色
（经 `processAccentColor`，与 App 同一条路径）× 明暗两模式 = 36 个样本。

| 方案 | 最小 ΔE | 达标(≥5) | 理想(≥10) | 最小对比度 |
|---|---|---|---|---|
| Material 经典 scheme（`CoverPalette` 的 a1/a2/a3） | **5.1** | 36/36 | **0/36** | 5.74 |
| **本版：主题色 + 同亮度三色组（Δh₂=+240°、Δh₃=+120°、C=48）** | **10.1** | 31/36 | **31/36** | 1.12 |

⇒ **Material 的角色色不能直接用**：a2/a3 的彩度只有 16/24、色相又挨着，
36 个样本里 **0 个**达到"一眼分辨"的 ΔE ≥ 10。本版改用**三色组**（色相两两相隔 120°、
彩度 48、tone 与主题色相同 —— 只换色相与彩度、不换亮度，所以"哪一段更亮"这个既有读法不被伪造），
最小 ΔE 10.1、31/36 达到理想档。

对比度那 5 个不达标的样本（如素白主题 + 浅色底 = 1.12）**是主题色本身的对比度**，
不是本方案引入的：今天的单色波形用的是同一个主题色，同样看不见。详见 PROBE-SUMMARY 的遗留风险。

### 4.1 频段 → 角色的映射（由 §2.3 的实测占比决定）

| 频段 | 角色 | 依据 |
|---|---|---|
| 低 | secondary | 实测占比 **0.33** |
| **中** | **primary（主题色本身）** | 实测占比 **0.66** —— 中频占 2/3 的时间，把主题色给它，波形大多数时候仍是主题色 |
| 高 | tertiary | 实测占比 **0.00** |

## 5. 对 v3.2.2 的约束

1. **不得硬切**（铁律 30）：过渡时长 100ms，且过渡期间不接受新切换。
2. **过渡权重必须并入重绘判据**：它是一段逐帧动画，漏了就会"颜色走到一半停住"
   （与 v2.8.0 峰值保持同形状的坑）。
3. **颜色三色化不得引入每帧 HCT 计算**：`paletteFor` 在组合期按 `主题色 + 明暗` 缓存，
   帧路径只做三元素加权 + 通道插值。
4. **降级必须退回单色**：特征不可用时权重不可信，渲染侧用主题色单色画（见 `BandColorRoles` 的 try/catch 退路）。
