# Ncrust v2.5.4-gpl

**versionCode 45** · Android 7.0（API 24）起 · GPLv3 · 无新增权限、无自建 API、无 Termux、**无任何新增上报**

> 探针：`docs/verification/v2.5.4/PROBE-SUMMARY.md`（五份，含两处**推翻任务书前提**的记录）
> 证据：`docs/verification/v2.5.4/EVIDENCE.md`（单测与真机验证分开写）

## 一句话

修好了三件用户能感知的事（**搜索历史里的 QQ 歌不再被当成 ncm**、
**平板横屏终于有音频可视化波浪条**、**竖屏播放托盘改成实时歌词 + 歌名/作者/音源**），
给 QQ 兜底路径装上了**只落本地**的频率统计，并**第一次建立了 release 包的性能基线**。

## 1. 竖屏播放托盘改版 ✨

托盘从「歌名 / 艺人 · 音源」变成：

```
实时歌词            ← 第一行，跟随播放按行变化
歌名  作者  音源     ← 第二行
```

- **实时歌词是行级的**：一行持续期间托盘**零重组**（单测：51 个 2Hz 采样点只产出 5 次新值）；
- **无歌词时**第一行留白，托盘高度不跳（真机上抓到「空行会塌」的问题并已修）；
- **长歌词**按一行省略号处理，**不做跑马灯**（常驻组件持续排帧不值得）；
- **点击**：点歌词 → 展开播放器并直接看歌词；点歌名 → 展开播放器；
  **点作者 → 进艺人页**；点音源角标 → 展开；
- 真机验证：Android 7.0 手机上 12 秒内歌词从
  `残酷な天使のように 少年よ神話に…` 换成 `蒼い風がいま 胸のドアを叩いても`。

## 2. 平板横屏的音频可视化波浪条 🐛

**根因不是「条件没满足」，而是反过来的**：平板横屏时「宽屏」条件**满足**了，
于是它走的是**宽屏两栏**布局 —— 而波浪条只挂在「用户点过 ⤢ 大屏幕模式」的那条分支里。
更糟的是**平板上根本没有那个 ⤢ 按钮**（它只在竖屏控制条里），
所以这个功能在平板上是**结构性不可达**的。

修法：挂载判据抽成一个纯函数，用「最小宽度 ≥ 600dp」区分**平板**与**横过来的手机**
（后者不受影响），只在**「平板 + 横屏」**这一格由无变有：

| 形态 | 之前 | 现在 |
|---|---|---|
| 手机竖屏 | 无 | 无 |
| 手机横屏（非大屏模式） | 无 | 无 |
| 手机横屏（大屏模式） | 有 | 有 |
| 平板竖屏 | 无 | 无 |
| **平板横屏** | **无** | **有** |
| 平板横屏（大屏模式） | 有 | 有 |

六格矩阵由单测逐个钉住。

## 3. 搜索历史的音源丢失 🐛

任务书说「QQ 歌被认成 ncm」，探针把症状定得更准：
**播放路径其实认得出是 QQ（id 里的标志位），但 `songmid` 丢了 ⇒ 一律取不到链** ——
点一条历史，歌被跳过，还弹一条方向错误的「可切到 ncm」提示。

- 历史记录现在**同时存音源、songmid、media_mid**；
- **老记录**按 id 的标志位推断音源（这是唯一**可证明**的规则 ——
  QQ 的裸 songid 与 ncm 的 id 区间重叠，拿区间猜会误判）；
- **老 QQ 记录补不回 songmid**（散列不可逆，本版**不猜**）：
  点它会明确提示「这条记录来自旧版本，缺少音源标识，已为你重新搜索」并把它填回搜索框，
  **不再静默跳过**；「添加到下一首 / 加入库」对这类记录不显示；
- **不丢历史**：新旧两种落盘格式同时可读，坏条目只丢那一条（旧实现是一个字节坏了整段消失）。

**顺带修掉一个会让搜索历史静默消失的隐患**：真机上那张表的 JSON 字段名是被
R8 混淆过的单字母（`{"a":…,"e":…}`），下一次构建的混淆映射一变，老数据就一条都读不出来。
本版把字段名固定成显式契约，并且**读路径同时认三种历史格式**。

## 4. QQ 兜底路径的本地频率统计 📊

- 统计「服务端没给 QQ songid、只能按 songmid 散列造 id」的**触发频率**，
  以及这些曲目的**取链成功率**与**真的播出声率**；
- **只落本地私有目录，不上报**（这份代码里没有任何网络调用）；
- debug 包多一个读出入口（logcat `QqProbe` + 落盘），release 包看不到那一行；
- 首次真机样本：解析 30 首 QQ 曲目，**没有一首**触发兜底。
  「跑满 1~2 天」的长期窗口尚未完成，如实列在缺口清单里。

## 5. 转发属性量化 📈

- **结论：不需要优化。** 231 条转发属性是零分配的 getter，
  且在 release 产物里**已被 R8 全部内联**（120 条里 0 条残留方法体，每次访问只剩 2 条 `iget`）；
- 但**本版之前没有任何 release 性能基线**，所以新增「设置页滚动」基准
  （设置页是转发属性最密集的一面：66 处读点 vs 播放器 44、首页 0），
  连同既有的首页滚动 / 播放器展开 / 冷启动一起，在 **release 包**上建立了第一条基线。

| 项 | 结论 |
|---|---|
| 覆盖安装 | 支持（签名一致，`versionCode` 43 → 45） |

## 已知问题与遗留风险

1. **平板上仍然进不了「大屏幕模式」**（⤢ 入口只在竖屏控制条里）——
   本版修好了波浪条，但那个入口的缺失是另一件事，未在本版动；
2. **搜索历史列表不显示音源角标** —— 恢复是正确的，但用户在列表里仍分不出
   两条同名历史哪条是 QQ；
3. **`ncrust_offline` 的离线曲目索引仍是 R8 单字母字段名**（同类隐患，本版未修）；
4. **QQ 曲目的播放行为会被上报给 ncm 的推荐接口**（`PlayReporter` 没有音源闸门），
   与代码里「不上报 QQ 播放行为」的注释矛盾 —— 探针发现，本版未改；
5. **QQ 兜底统计的长窗口样本未跑满**；且探针在真实搜索响应里**没观察到**
   服务端不下发 `id` 的样本，所以兜底率有可能天然恒为 0。

## 未验证缺口（不许用单测冒充真机证据）

见 `docs/verification/v2.5.4/EVIDENCE.md` §6 的十条清单，其中最要紧的三条：

- **WGR-W09 平板真机的横屏波浪条 A/B**：执行期间该平板处于锁屏，无解锁凭据，
  改用一个**显示参数逐项相同**（sw800dp / 1280×800dp / 320dpi / landscape）的模拟器做的 A/B；
- **平板横屏下波浪条随音乐跳动**：模拟器上没有在播的音频流，只证明了「挂载发生了」；
- **拨号盘式的高频交互**（点作者 / 点歌词）没有逐一手工验证。
