# v2.6.2-gpl

**versionCode 50** · `minSdk 24`（Android 7.0 / 3 GB RAM 可用）· GPLv3（原代码 MIT）· 无新增权限

> **P0 hotfix。** 只修一个用户可见缺陷 + 补它的回归面，不引入新功能、不顺手改别的。
> qm 曲目的「转到专辑」以前会把用户送到**另一张专辑**的页面
> （陈奕迅《富士山下》→ 陈小云的《百万金曲》），或者干脆**毫无反应**。
> 现在它进的是**正确的 QQ 专辑页**；拿不到可信身份时改为**跳搜索并给出提示**，
> 而不是猜一张专辑出来。

## 1. 探针结论（先探针，后改代码）

> 完整数据：`docs/verification/v2.6.2/PROBE-SUMMARY.md`
> 证据索引：`docs/verification/v2.6.2/EVIDENCE.md`
> 接口取证脚本可重跑（匿名、无 cookie）：`ncrust-gpl/tools/probe-album-{id-collision,cross-domain,detail-identity}.py`

### 1.1 复现路径与稳定性

| 设备 | 版本 | 路径 | 修复前 | 稳定性 |
|---|---|---|---|---|
| PCL110（OPPO / Android 16） | v2.6.1-gpl | 搜索 `Eason Chan` → 长按 QQ《葡萄成熟时》→ 转到专辑 | **《爱的供养》/ 邓杰** | 2/2 |
| S6（三星 G9209 / Android 7.0） | v2.6.0-gpl | 同上（QQ《富士山下》） | **《百万金曲 陈小云2 苦恋梦 免失志》/ 陈小云** | 2/2 |
| S6 | v2.6.0-gpl | 冷启动恢复的 QQ《稻香》→ 转到专辑 | **毫无反应**（页面不变、无提示、无日志） | 2/2 |

**两台设备落到两张不同的错专辑** ⇒ 排除「某个写死的 fallback 值」，
指向「QQ 的数字 id 恰好命中了 ncm 的哪张专辑」。

### 1.2 两个编号空间互不相通（实测撞号矩阵）

| QQ 曲目 | QQ `album.id` | QQ `album.mid` | 同专辑的 ncm id | 拿 QQ 数字 id 查 ncm |
|---|---|---|---|---|
| 富士山下 / 陈奕迅《What's Going On...?》 | `22276` | `004Z85XP1c25b7` | `6451` | **《百万金曲 陈小云2 苦恋梦 免失志》/ 陈小云** |
| 葡萄成熟时 / 陈奕迅《U 87》 | `7879` | `003J6fvc0bVJon` | — | **《爱的供养》/ 邓杰** |
| 晴天 / 周杰伦《叶惠美》 | `8220` | `000MkMni19ClKG` | `18905` | 404（静默失败） |
| 江南 / 林俊杰《第二天堂》 | `8036` | `000y5gq7449K9I` | `10804` | 404 |

拿一个源的 id 去查另一个源，**不是「查不到」而是「查到另一张真专辑」**：
封面、发行日期、厂牌、曲目数一应俱全，用户会以为**这个应用的专辑数据整体是错的**。

### 1.3 根因：v2.6.1 的孪生缺陷，四个环节一一对应

| # | 环节 | 艺人（v2.6.1 已修） | 专辑（本版） |
|---|---|---|---|
| 1 | 映射层丢掉源内字符串身份 | `singer[].mid` 被丢 | **`album.mid` 被读出来了，但只喂给了封面 URL**；`AlbumItem` 没有字段装它 |
| 2 | 跳转层不看 `song.musicSource` | 只读 `artists[0].id` | 只读 `album.id` |
| 3 | 老路由 source 写死 | `artist/{id}` → `NETEASE` | `album/{id}` → `NETEASE` |
| 4 | 身份不可信时静默失败 | 补 id 回落打**ncm**接口 ⇒ 查空 | **连回落都没有** ⇒ 直接 no-op |

> 第 4 条是**任务书判断被本探针修正**的那一条：任务书假设「有回落逻辑，回落打的是某个源的接口」。
> 实测专辑分支**没有任何回落** —— 这比艺人那处更难查：连一次失败的网络请求都不发，
> logcat 里一条都不留（`probe-logcat.md`）。

### 1.4 一个容易踩的坑：`pmid` 不是专辑身份

QQ 搜索响应里专辑对象同时给三个候选：
`id`（数字）、`mid`（albumMID，`004Z85XP1c25b7`）、
**`pmid`（封面照片 id，`004Z85XP1c25b7_5` —— 尾部 `_N` 是封面序号）**。
现有代码**优先取 `pmid`**（对封面是对的），照抄它当路由参数就是错的形状。
实测 QQ 服务端**碰巧能容忍**把它当 `albumMid` 传（内部会剥掉 `_N`），
但那是服务端的宽容、不是契约 —— 本版把身份显式钉在 `mid` 上，
并让值域闸门（base62，`_` 不合法）把 `pmid` 挡在门外。

### 1.5 入口有几个

**动作 1 个构造点、宿主页面 9 个、出口 1 个**（首页 / 库页 / 搜索 / 歌单 / QQ 歌单 /
本地歌单 / 专辑 / 艺人 / 播放器卡），全树只有 `MainActivity.kt:2613` 一处构造这个动作。
所以本版**不需要**像 v2.6.1 那样逐个入口改代码。

## 2. 修复说明（用户看得见的变化）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| QQ 曲目 →「转到专辑」 | 跳到**另一张真实存在的专辑**，页面渲染完全正常 | 进**正确的 QQ 专辑页** |
| QQ 曲目（老队列 / 冷启动恢复 / 老收藏）→「转到专辑」 | **毫无反应**：页面不变、无提示、logcat 一条不留 | 切到搜索 tab 并预填关键词，**给一句提示**，并记 `AlbumNav` 日志 |
| ncm 曲目 →「转到专辑」 | 正确 | 正确（**零回归**，真机 A/B 已验证） |

改动要点（细节见 `docs/verification/v2.6.2/CHANGELOG-v2.6.2.md`）：

1. `AlbumItem` 新增 `mid`（可空 + 默认值 + 显式 `@SerializedName`）；
   `QqSongMapper` / `QqCatalogMapper` 两条链路一起填，**封面与身份拆开**：
   封面继续 `pmid ?: mid`（一行未改），身份**只认 `mid`**。
2. 新增 `source/AlbumNavigator.kt`：`Direct(source, id)` / `Search(keyword, reason)` /
   `Unavailable` 三态，**类型上不存在「跳到另一个源」**。主判据是 source，
   值域闸门是兜底，置信度闸门复用 `MatchConfidence.mergeable`。
3. 值域判据抽成唯一落点 `source/SourceIdDomain.kt`（v2.6.1 的 `ArtistNavigator`
   改为委托它，**行为零变化**，原 17 条单测一行没动）。
4. 出口收敛到 `MainActivity.navigateToAlbum`；删掉那处多余的线程切换与那处「没有回落」。
5. 收藏专辑表补 `albumMid`（显式 `@SerializedName` + `SCHEMA_VERSION` 2→3），
   老形状三读法原样兼容；**无 `albumMid` ⇒ 标记「身份不可信」⇒ 跳搜索，绝不猜**。
6. 新增 8 语言文案 `albumNavSearchFallback`。

**零新增路由**：`NavRoutes.album(source, id)` 那条带音源的两段路由 v2.4.0 就有了，只是这条路一直没用它。

## 5. 未验证缺口（**如实列出，不伪造**）

| 缺口 | 说明 |
|---|---|
| 9 个宿主**逐个**真机点一遍 | 只抽测了 搜索页 / 库页 / 播放器卡二级菜单。剩下的（首页 / 歌单 / QQ 歌单 / 本地歌单 / 专辑页 / 艺人页）**结构上完全同源** —— 都经 `MainActivity.showSongMenu` 汇到同一张 `SongMenuSheet`，`SongItem` 也来自同一批映射函数 —— 但**没有逐个点过** |
| 收藏专辑表 `albumMid` 的**真机迁移** | 三种落盘形状有单测覆盖（含「缺失 vs 空串」的两义性），但真机收藏列表里目前**全是 ncm 专辑**（`mid` 恒为 null），所以「老条目读出来 `mid=null`」只在单测里验证过 |
| QQ 歌单 / 本地歌单页里的 QQ 曲目 | 未抽测（同上，结构同源） |
| 折叠态播放器卡的**命中带**吞掉二级菜单最后几行 | **既有缺陷，与本 P0 无关，本版不修**。WGR-W09 实测：`y=648` 的「加入歌单」可点、`y≥1320` 的「转到歌手/转到专辑/单曲信息」打不到；真机验证时靠清空队列或转竖屏绕开。已记入未修清单 |
| 「跳到一张看起来正常的错专辑」的**用户侧可发现性** | 修复前这一档没有任何日志；本版补了成功路径的 `AlbumNav` 日志，但**历史错误无法追溯** |
