## 一句话

**修好了「QQ 歌曲加入库后一刷新就没了」**，并补上三件你点得着的东西：
歌手页的「全部播放」（跨源混播不重复）、库页歌单的**列表 / 卡片**布局切换、
以及每个源区块的**手动折叠**。

## 1. P0：QQ 歌曲「加入库」后刷新消失（已修）

### 你会看到的变化

- 「加入库」之后，**下拉刷新 / 切页面 / 重启手机都不会再消失**；
- qm 的歌也能真正待在你的库里了（以前它只是**看起来**进去了）；
- 提示不再说谎：只有真的写进去了才弹「已加入库」；
- 一首歌**在库里删掉之后不会再自己回来**（这是「只加不减 + 墓碑」的正确一半）。

### 根因（一句话）

「加入库」写进的是**ncm 红心歌单的镜像**，而每次进库页都会用**云端红心列表重建这张表** ——
不在云端列表里的条目会被直接丢掉、并立刻写回磁盘。
QQ 歌曲的编号和 ncm 的编号是**两套不相交的号段**，所以 QQ 歌曲**永远**不在云端列表里
⇒ 每次刷新丢一次，100% 复现。

### 真机受控 A/B（S6 / Android 7.0）

同一台设备、**同一份磁盘输入**（147 首真实收藏 + 1 首本地加入的 QQ 歌），只换应用版本：

| | v2.5.6 | v2.6.0 |
|---|---|---|
| 真实刷新跑完之后 | **147 首 —— QQ 那首没了** | **148 首 —— 还在** |

原始 prefs 与 logcat 留档在 `docs/verification/v2.6.0/verification/p0-*.xml`。

### 同时修掉的另外两条数据丢失路径

1. **落盘去抖窗口**：用户动作以前走 300ms 去抖，加完歌立刻划掉应用就丢。现在用户动作**立即落盘**；
2. **空表覆盖**：以前「内存里还没加载」与「内存里确实是空的」是同一个取值 ——
   于是**收藏一张专辑**这个动作有可能把你整张收藏单曲表清空。现在三个键各自独立判断。

### 顺带修掉的跨源泄漏

QQ 歌曲的编号以前会被原样发给**ncm**的收藏接口（一个 ncm id 空间里不存在的号）。
现在在收藏动作的**唯一出口**加了闸门，判据与 v2.5.5 修的播放上报闸门**共用同一个谓词**，
并有一条「两条链路逐值一致」的穷举单测钉住。

## 2. P1：歌手页「全部播放」（新增）

- 歌手页的曲目列表上方多了一个 ▶ 与一个规模提示（「N 首」）；
- 点它 = **替换当前队列**并从第一首开始播（不是追加 —— 追加会把你队列里剩下的歌夹在中间）；
- **跨源混播会自动去重**：同一首歌在 ncm 和 QQ 都有时**只播一遍**；
- **宁可多播一遍，不会误删一首**：判据用仓库里那套用 230 首真实样本标定过的匹配规则
  （曲名 + 艺人 + 时长 + 版本标记）。实测「艺人一致但时长差 > 30s」的那 15 条
  **全部是同名不同版本**（伴奏 / Live / 加长版）—— 这一类**保留两份**，
  因为把用户想听的那一首删掉比多播一遍严重得多；
- 顺序就是你在界面上看到的顺序（含「双源 / 只看 ncm / 只看 QQ」的口径过滤）；
- 列表为空时按钮不出现。

## 3. P1：库页歌单的列表式 / 卡片式切换（新增）

- 库 → 歌单，**右上角两个小按钮**（列表式 / 卡片式），点一下立即生效；
- **三个区块统一**（本地歌单 / ncm / qm）—— 这一页其实是**三个**源，
  只统一两个会留下一个「本地是卡片、另外两段是列表」的半切换页面；
- **重启后保持**（存在 `ncrust_settings`，与主题、语言同一处）；
- 两种规格：
  - **列表式**：48dp 小封面 + 歌单名 + 「N 首」/来源；
  - **卡片式**：大封面 + 歌单名 + 歌曲数，窄屏 2 列网格；
- **切换不会重新加载数据、也不会丢滚动位置**（没有换滚动容器，只换列数）。

### 关于默认值（需要你知道的一件事）

改造前这一页**本身就是混合的**（本地/ncm 是卡片、QQ 是整行），所以**不存在**
「谁都不变」的默认值。本版默认 **卡片式**：它保留面积最大的两段的现状，
只让 QQ 那一段从整行变成卡片。不喜欢的话点一下「列表式」即可，之后会记住。

## 4. P2：歌单区块手动折叠（新增）

- 库 → 歌单，**点区块标题那一行**即可收起 / 展开（本地歌单 / ncm / qm 各自独立）；
- 展开时标题右侧显示「收起」，收起时显示「**展开全部 N 个**」——
  带上数字，你才知道值不值得展开；
- **永远不会自动折叠**。这不只是一句承诺：折叠状态的类型上**只有「切换」一个入口**，
  还有一条反射单测把这个事实钉住（将来有人加「太多就自动收起」会让测试变红）；
- **重启后保持**；
- 布局切换按钮**不受折叠影响**（否则收起区块会把出口一起收掉）。

## 6. 与用户报告的一处出入（如实说明）

用户报告说「qm**歌单详情**里长按入库」。本版探针查明：**那张菜单里今天没有「加入库」**
（源码里传给它的动作列表是空的；阳性对照：ncm 歌单详情同一位置有两条）。
QQ 歌曲可到达「加入库」的入口是**播放器卡片上的收藏按钮**与**搜索结果 / 搜索历史的菜单**。

修复作用在**所有入口共享的存储与同步层**，所以走哪个入口都能修好；
但如果你手上的复现路径确实是「QQ 歌单详情 → 长按 → 某个菜单项」，
请把那张菜单截图发出来（含版本号），我下一版按它对齐。
