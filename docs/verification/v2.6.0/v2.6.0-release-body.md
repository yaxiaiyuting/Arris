# v2.6.0-gpl

> `versionCode 48` · 基线 `v2.5.6-gpl`（47）· tag [`v2.6.0-gpl`](https://github.com/yaxiaiyuting/Ncrust/releases/tag/v2.6.0-gpl)
> 探针：`docs/verification/v2.6.0/PROBE-SUMMARY.md` · 证据：`docs/verification/v2.6.0/EVIDENCE.md` · 更新说明：`docs/verification/v2.6.0/CHANGELOG-v2.6.0.md`

## 一句话

**修好了「QQ 歌曲加入库后一刷新就没了」**，并补上三件你点得着的东西：
歌手页的「全部播放」（跨源混播不重复）、库页歌单的**列表 / 卡片**布局切换、
每个源区块的**手动折叠**。

---

## 1. P0 · QQ 歌曲「加入库」后刷新消失（已修）

**你会看到的变化**

- 「加入库」之后，下拉刷新 / 切页面 / 重启手机**都不会再消失**；
- qm 的歌也能真正待在你的库里（以前它只是**看起来**进去了）；
- 提示不再说谎：只有真的写进去了才弹「已加入库」；
- 一首歌在库里**删掉之后不会再自己回来**（「只加不减 + 墓碑」的正确一半）。

**根因（一句话）**：加入库写进的是**ncm 红心歌单的镜像**，而每次进库页都会用
**云端红心列表重建这张表** —— 不在云端列表里的条目会被直接丢掉并立刻写回磁盘。
QQ 歌曲的编号与 ncm 是**两套不相交的号段**，所以 QQ 歌曲**永远**不在云端列表里
⇒ 每次刷新丢一次，100% 复现。

**真机受控 A/B（S6 / Android 7.0）** —— 同一台设备、**同一份磁盘输入**
（147 首真实收藏 + 1 首本地加入的 QQ 歌），只换应用版本：

| | v2.5.6 | v2.6.0 |
|---|---|---|
| 真实刷新跑完之后 | **147 首 —— QQ 那首没了** | **148 首 —— 还在** |

原始 prefs 与 logcat：`docs/verification/v2.6.0/verification/p0-*`。

**同时修掉的另外两条数据丢失路径**

1. 落盘去抖窗口：以前用户动作走 300ms 去抖，加完歌立刻划掉应用就丢 ⇒ 现在**立即落盘**；
2. 空表覆盖：以前「内存里还没加载」与「确实是空的」是同一个取值 ⇒
   **收藏一张专辑**这个动作有可能清空你整张收藏单曲表 ⇒ 现在三个键各自独立判断。

**顺带修掉的跨源泄漏**：QQ 歌曲的编号以前会被原样发给**ncm**的收藏接口。
现在在收藏动作的唯一出口加了闸门，判据与 v2.5.5 修的播放上报闸门**共用同一个谓词**，
并有一条「两条链路逐值一致」的穷举单测钉住。

## 2. P1 · 歌手页「全部播放」（新增）

- 歌手页曲目列表上方多了一个 ▶ 与规模提示（「N 首」）；
- 点它 = **替换当前队列**并从第一首开始播（不是追加）；
- **跨源混播自动去重**：同一首歌在 ncm 和 QQ 都有时**只播一遍**；
- **宁可多播一遍，不会误删一首**：判据用仓库里那套以 230 首真实样本标定过的匹配规则
  （曲名 + 艺人 + 时长 + 版本标记）。实测「艺人一致但时长差 > 30s」的 15 条
  **全部是同名不同版本**（伴奏 / Live / 加长版）⇒ 这一类**保留两份**；
- 顺序就是界面上看到的顺序（含「双源 / 只看 ncm / 只看 QQ」的口径过滤）；
- 列表为空时按钮不出现。

## 3. P1 · 库页歌单的列表式 / 卡片式切换（新增）

- 库 → 歌单，**右上角两个小按钮**（列表式 / 卡片式），点一下**立即生效**；
- **三个区块统一**（本地歌单 / ncm / qm）—— 这一页其实是三个源；
- **重启后保持**；
- **列表式**：48dp 小封面 + 歌单名 + 「N 首」/来源；
  **卡片式**：大封面 + 歌单名 + 歌曲数，窄屏 2 列网格；
- **切换不重新加载数据、也不丢滚动位置**（没换滚动容器，只换列数）。

> **关于默认值**：改造前这一页**本身就是混合的**（本地/ncm 卡片 + QQ 整行），
> 所以**不存在**「谁都不变」的默认值。本版默认**卡片式** —— 保留面积最大的两段的现状，
> 只让 QQ 那一段从整行变成卡片。不喜欢就点一下「列表式」，之后会记住。

---

## 4. P2 · 歌单区块手动折叠（新增）

- 库 → 歌单，**点区块标题那一行**即可收起 / 展开（三个源各自独立）；
- 展开时右侧显示「收起」，收起时显示「**展开全部 N 个**」（带数字，你才知道值不值得展开）；
- **永远不会自动折叠**。这不只是承诺：折叠状态的类型上**只有「切换」一个入口**，
  还有一条反射单测把这个事实钉住；
- **重启后保持**；布局切换按钮**不受折叠影响**（否则收起区块会把出口一起收掉）。

## 6. 与用户报告的一处出入（如实说明）

报告说「qm**歌单详情**里长按入库」。探针查明：**那张菜单里今天没有「加入库」**
（源码里传给它的动作列表是空的；阳性对照：ncm 歌单详情同一位置有两条）。
QQ 歌曲可到达「加入库」的入口是**播放器卡片上的收藏按钮**与**搜索结果 / 搜索历史的菜单**。
修复作用在**所有入口共享的存储与同步层**，走哪个入口都能修好；
但如果你手上的复现路径确实是「QQ 歌单详情 → 长按 → 某个菜单项」，
请把那张菜单截图发出来（含版本号），下一版按它对齐。

## 7. 安装

- 覆盖安装即可（`versionCode 48 > 47`），**不需要卸载**，收藏与登录态都会保留；
- 首次启动会把旧的收藏表**自动迁移**成带来源标记的新形状（老数据全部解释为「同步来的」），
  迁移过程逐条容错，坏掉一条只丢那一条；
- `minSdk 24`（Android 7.0）。
