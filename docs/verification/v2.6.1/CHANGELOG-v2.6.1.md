# Ncrust v2.6.1-gpl（hotfix）

**发布日期**：2026-09-26
**基线**：v2.6.0-gpl（versionCode 48）
**本版**：versionCode **49**
**性质**：P0 hotfix，只修一个用户可见缺陷 + 补它的回归面；不引入新功能。

---

## 一句话

qm 曲目的「转到歌手」以前会把用户送到**另一个歌手**的页面
（《稻香》→ 马洪波）。现在它进的是**正确的 QQ 艺人页**；
拿不到可信身份时改为**跳搜索**并给出提示，而不是猜一个人出来。

---

## 修了什么

### P0：QQ 曲目「转到歌手」跳到错误艺人

**复现**（真机，两台）：

| 设备 | 路径 | 修复前 |
|---|---|---|
| WGR-W09（华为平板 / Android 12） | 搜索 `Jay Chou` → 长按 QQ《晴天》→ 转到歌手 | **马洪波**（专辑 5 / 单曲 40） |
| PCL110（OPPO 手机 / Android 16） | 同上 | **马洪波** |
| PCL110 | 冷启动后（当前歌由状态恢复）→ 播放器点歌名 → 转到歌手 | **毫无反应** |

**根因**（探针结论，两条独立缺陷）：

1. **QQ 的 `singerMID` 在映射层被丢掉。** QQ 的 `singer[]` 条目同时给
   数字 `id`（QQ 域）与字符串 `mid`（singerMID，base62），旧映射只取了前者。
   而跳转用的老路由 `artist/{artistId}` 在页面里把音源**写死**成 ncm ——
   于是 QQ 的 `4558`（周杰伦）被当成 ncm 艺人 id 查，命中**马洪波**。
2. **补 id 的回落打错了源。** 冷启动恢复的曲目只有艺人**名字**、没有 id，
   而"补一次详情"打的是**ncm**接口，QQ 曲目的 id 带 bit62 标志位必然查空
   ⇒ 什么分支都不匹配 ⇒ **静默失败**。

接口实测（匿名可复现，脚本已入库）：

| QQ 歌手 | QQ `singer.id` | 当成 ncm id 查出来 |
|---|---|---|
| 周杰伦 | `4558` | **马洪波**（专辑 1 / 单曲 32，页面看起来完全正常） |
| 林俊杰 | `4286` | 刘子译（专辑 0 / 单曲 0，空页面） |
| 陈奕迅 | `143` | 404 |

**修法**：

- QQ 映射层保留 `singerMID`（`ArtistItem.mid`，可空 + 默认值）；
- 新增 `ArtistNavigator`：艺人跳转的**唯一**身份判定，产出
  `进本源艺人页` / `跳搜索` / `什么都不做` 三态 —— **类型上不存在"跳到另一个源"**；
- 值域闸门：ncm 吃十进制、QQ 吃 base62 的 `singerMID`，
  **纯数字的 QQ `singerID` 在 QQ 域不是合法身份**，在闸门上就被拦下；
- 置信度闸门：任何跨源候选都必须拿到 `MatchConfidence.mergeable`（>= MEDIUM）
  **且**目标值域合法，否则跳搜索；
- 长按菜单与播放页托盘收敛到**同一个出口**（旧代码是两个入口两套判据）。

### 顺带修掉的同类问题

| 问题 | 现状 |
|---|---|
| **播放页托盘作者名**同样跳错（`onArtistClick` 只传裸数值 id） | **已修**，与长按菜单同一出口 |
| 点托盘作者名在冷启动后只弹一个"点了也没反应"的菜单（`id == null` 时回落） | **已修**，改为直接判定 |
| `PlaylistCacheCodec` 的扁平 DTO 会丢掉 `mid`（QQ 歌单入口会静默降级为跳搜索） | **已修** + 单测 |
| 剪贴板链接 / 音乐人推荐卡 / 搜索艺人 tab 三个"按构造就是 ncm"的入口没有**写出**音源 | **已修**（显式写 `MusicSource.NETEASE`）+ 源码扫描守卫 |
| 这条路径在 release 包上**零日志**（无法线上定位） | **已修**，新增 `TAG_ARTIST_NAV` 日志 |

## 用户能感觉到的变化

1. **QQ 曲目的「转到歌手」进的是 QQ 源的这位歌手**，不再跳到不相干的人。
2. 少数情况下（老数据、服务端没给 `singerMID`）会**跳到搜索结果**并提示
   「未找到该歌手的准确身份，已为你搜索」—— 而不是静默无反应，
   也不是把你送到另一个人那里。
3. ncm 曲目的行为**逐字节不变**（回归已验）。

## 本版**没有**修的（如实列出）

| 未修项 | 原因 |
|---|---|
| 二级菜单「**转到专辑**」对 QQ 曲目同样错（QQ 的 `album.id` 被当 ncm album id） | 需要 QQ 的 `albumMID`，而 `AlbumItem` 不带。为它再加一次跨表迁移 + 5 张持久化结构的回归，会把一次 hotfix 的面扩大到半个数据层 |
| 搜索页「艺人」tab 只有 ncm 结果 | 这是**缺失的功能**，不是错误跳转。QQ 艺人搜索端点已存在，但只被跨源匹配使用 |
| `SearchHistoryManager.addArtist` 不落 `source` | 当前唯一写入方是 ncm，行为正确；将来写入 QQ 艺人时由值域闸门兜住 |
| S6（Android 7.0）上未复测 | 该机上长按歌曲行会被播放器拖拽层吃掉，取不到二级菜单（见 `probe-artist-jump.md` §6）。结论由 PCL110 + WGR-W09 两台构成 |
| 华为控制中心卡片 | 按纪律**不碰** |

## 新增的三条铁律（AGENTS.md 26/27/28）

26. **跨源身份跳转必须携带 source，不得只传数值 ID。**
27. **匹配置信度不足时宁可跳搜索，不可跳错误艺人。**
28. **跳转错误比找不到更严重 —— 找不到用户能理解，跳错会让用户以为数据错乱。**

第 28 条不是修辞，它是本次三档失败的实测排序：只有"跳到真人"那一档会让用户
对整个数据层失去信任（页面有头像、有专辑、有单曲，看起来完全正常）。
