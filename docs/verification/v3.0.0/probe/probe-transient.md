# 探针 3.2 · 瞬态检测方案（v3.0.0）

> **性质**：只读探针 + 已落地实现的判据说明。每条结论给 `file:line` 或实测数据。
> **证据分级**：**【事实】**= 源码；**【实测】**= JVM 数值复算 / 仪器探针；**【估算】**= 代码算式；**【未验证】**= 明确没确认。

---

## 1. 结论先行

**瞬态检测放在音频线程、每缓冲判定一次**，判据是「**相对慢速基线的增量** ∧ **超过衰减的峰值记忆** ∧ **不在冷却窗口内**」，
低频带与全带**两条并列**（前者抓底鼓/贝斯鼓点，后者抓军鼓/拍手/高频击打）。

**为什么不是留在 UI 帧循环里**（v2.9.0 的做法）：UI 判据读的是「最新一根柱」，
而一根柱 = 一次 `handleBuffer`。**缓冲率高于帧率时，一帧里到达的多根柱只有最后一根被看到**
—— 前面那些柱里的击打**永远不被判定**。单测
`TransparentWaveformSinkTest.motion features keep running when only the visualizer is off`
与 §5 的实测缓冲率一起说明这不是理论风险。

## 2. 候选方案与取舍

| 方案 | 需要 FFT | 本版是否采用 | 理由 |
|---|---|---|---|
| 谱通量（spectral flux） | **是** | ❌ | 铁律 28 未翻案；且要分帧 + 窗函数（本条数据通路没有） |
| 高频含量（HFC） | 否（一个一阶高通即可） | ✅ **部分** | `high = x − LP(2k)` 就是它；但单独用它漏掉底鼓（能量在低频） |
| 能量包络的正向一阶差分 | 否 | ✅ | 本版的核心：`值 − 慢速基线` |
| 低频通道的突变（v2.9.0 已有） | 否 | ✅ | 与上面并列的第一条判据 |
| 复杂域/相位偏差 | 需要 STFT | ❌ | 同「谱通量」 |

## 3. 判据的完整定义（**【事实】**）

实现：`AudioFeatureExtractor.updateTransient`（`AudioFeatureExtractor.kt:419-472`）。

```
每个缓冲（音频线程，一次）：
  dt      = 样本数 ÷ 声道数 ÷ 采样率 × 1000        // 时间基准**现算**，不假设缓冲粒度
  k       = 1 − exp(−dt / 800ms)                   // 慢速基线系数，也现算
  lowJump = low − baselineLow        ；fullJump = full − baselineFull
  mem     = peak · exp(−dt / 250ms)                // 衰减的峰值记忆
  lowNovel  = low  ≥ mem_low  · 1.6
  fullNovel = full ≥ mem_full · 1.6
  → 更新基线；peak = max(mem, 当前值)
  → 冷却递减；冷却未过 ⇒ 直接返回
  onset = (lowNovel  ∧ low  ≥ 0.10 ∧ lowJump  ≥ 0.05 ∧ lowJump  ≥ baselineLow · 0.35)
        ∨ (fullNovel ∧ full ≥ 0.12 ∧ fullJump ≥ 0.05 ∧ fullJump ≥ baselineFull · 0.35)
  若 onset：冷却 = 90ms；transient = true；strength = clamp(max(lowJump, fullJump) / 0.20)
```

### 3.1 三个门槛各自解决什么

| 判据 | 解决什么 | 参数 |
|---|---|---|
| **相对慢速基线的增量**（绝对 + 相对） | 绝对门槛跨曲目不可用（母带压缩强的曲子永远不达标、安静曲子永远达标）。`baseline` 是 0.8s 时间常数的一阶低通 —— 它本身就是 Dixon 那条自适应阈值的形式 | `ONSET_ABS_MIN = 0.05`、`ONSET_REL_FACTOR = 0.35`（与 `WaveformEffectsState` 同值） |
| **衰减的峰值记忆** | **衰减尾巴被重复判定**。一次底鼓是一段带衰减的包络（60ms 衰减 ⇒ 240ms 内都还有能量）；只靠冷却窗口的话，冷却刚过的那一帧 `值 − 基线` 仍然很大 | `PEAK_MEMORY_TAU_MS = 250`、`ONSET_PEAK_RATIO = 1.6` |
| **冷却窗口**（毫秒，不是缓冲计数） | 一次击打只出一个瞬态；并给触发率一个硬上界 | `ONSET_COOLDOWN_MS = 90` |

### 3.2 「峰值记忆」是怎么定出来的（**【实测】**，合成轨道）

合成轨道：220 Hz 底噪（振幅 0.02）+ 每 500ms 一次 60 Hz 指数衰减击打（振幅 0.9、衰减 60ms），
8 秒；逐 1024 帧（23ms）缓冲喂入，数瞬态次数：

| 判据 | 判出的次数 | 期望 | 结论 |
|---|---|---|---|
| 只有冷却 180ms（v2.9.0 的常量） | 太多（同一击的尾巴被重复判定） | 16 | ❌ |
| 冷却 90ms + 「等包络落回谷底再武装」 | **21** | 16 | ❌ 固定比例参照在衰减慢的曲子上会失效 |
| 冷却 90ms + 「包络必须在上升」 | **21** | 16 | ❌ 被**每缓冲 RMS 的相位起伏**骗到（60Hz 正弦在 23ms 窗口里只有 1.4 个周期，逐缓冲 RMS 有 ±20% 抖动） |
| 冷却 90ms + **衰减的峰值记忆**（**只有低频带**） | **22** | 16 | ❌ **全带**那条判据没有同样的闸门，尾巴从全带侧漏进来 |
| 冷却 90ms + 衰减的峰值记忆（**低频带 + 全带各一份**） | **16** | 16 | ✅ |

> 这条表就是「为什么最终是这一组判据」的全部依据 —— 前四行都真的红过，
> 单测 `AudioFeatureExtractorTest.周期性鼓点被逐次抓出来` 钉住最后一行。

### 3.3 冷却 90ms 而不是 180ms（**【估算】** + 文献）

- 180ms ⇒ 触发率上限 **5.6 次/秒**；而 120 BPM 的八分音符是 16 次/秒、180 BPM 的四分音符是 12 次/秒
  ⇒ 快节奏曲目会把相邻击打**合并**（表现是「该跳的地方不跳」）。
- 90ms ⇒ 上限 **11 次/秒**，覆盖到 180 BPM 的八分音符；文献里听感可分辨的下界是 30ms 量级。
- **与 UI 回落判据（180ms）刻意不再同值**：那条跑在帧循环上（16~33ms 分辨率），放宽只会变噪声。
  单测 `AudioFeatureExtractorTest.瞬态判据的常量与 UI 回落判据同源` 钉住**方向**（≤）而不是等值。

### 3.4 时间基准必须现算（**【事实】**）

- `frameMs = 样本数 ÷ 声道数 ÷ 采样率 × 1000`（`AudioFeatureExtractor.kt:355-357`）；
- 基线系数 `k = 1 − exp(−dt/800ms)`（**每缓冲一次 exp**，`baselineCoefficient`）；
  早先写的是固定步长 0.026，实测会让时间常数随缓冲粒度漂移：
  21ms 缓冲 → τ≈0.8s，93ms 缓冲 → τ≈3.5s（慢设备上「慢速基线」变成「几乎不动的基线」）。
  单测 `基线系数按 dt 计算而不是固定步长` 钉住单调性与数值。
- 冷却按**毫秒**递减，不按缓冲计数。

## 4. 与 v2.9.0 低频通道的关系：**复用，不是新建**

- 复用：`low` 就是 v2.9.0 那条 150 Hz 一阶低通（`LOW_CUTOFF_HZ` 直接引用 `PcmRms.BASS_CUTOFF_HZ`），
  连递推都逐字相同 ⇒ 「波形柱状图的低频」与「瞬态判据的低频」不可能分叉。
- 新建的只有三样：**全带判据**（抓非低频击打）、**峰值记忆**（防尾巴重复判定）、
  **按毫秒的冷却**（v2.9.0 的 UI 判据按帧）。
- 消费方的切换是**互斥**的：`WaveformEffectsState.update` 与 `MotionClock.frame` 收到
  `transientCount >= 0`（特征链路可用）时**只**用外部信号，内置判据整个不跑
  ⇒ 不存在「同一次击打被判两次」。
  证据：`WaveformEffectsState.kt` 的 `NO_EXTERNAL_TRANSIENT` 分支与
  `MotionEnvelope.update(..., externalAvailable)`。

**它怎么影响本方案**：
- 若粒度粗（几千帧 = 几十 ms），「每缓冲一次判定」的时间分辨率就是几十 ms ——
  对 90ms 的冷却来说仍然够用（冷却本来就 > 一个缓冲），但**快鼓点会合并**；

## 6. 有界性（铁律 4）

| 量 | 上界 | 依据 |
|---|---|---|
| 瞬态触发率 | 1 / 90ms ≈ 11 次/秒 | 冷却窗口 |
| 每帧补触发的特效 | `MotionBindings.MAX_TRANSIENTS_PER_FRAME = 4` | UI 一帧最多补 4 次（长卡顿后不炸屏） |
| 波形条内的涟漪/粒子 | `RIPPLE_CAPACITY = 3` / `PARTICLE_CAPACITY = 16` | v2.8.0 的定长池，池满覆盖最旧 |
| 背景层的光晕/冲击波/粒子 | 4 / 2 / 40 | v3.0.0 的定长池，同上 |
| 数值 | 全部 `coerceIn` + `isFinite` | NaN 一旦进入缩放因子会让整层背景消失且**不抛异常** |

## 7. 未验证项

1. `ONSET_PEAK_RATIO = 1.6` 与 `ONSET_COOLDOWN_MS = 90` **没有**在多种真实曲风上做过 A/B
   （合成轨道 + 文献量级是全部依据）。
2. 真机上的**漏检率**（应该跳但没跳的比例）无法用现有工具量化 —— 只能靠观感复核
   （见 `verification/` 的录屏与帧时间数据）。
3. 6 声道 FLAC（QQ 臻品档）上的瞬态判据**未做端到端验证**（纯数学有单测覆盖）。
