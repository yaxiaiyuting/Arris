## 问题 1：无 FFT 前提下可实现哪些音频特征？

**答：可以实现全部四项 —— 三频段能量、瞬态、频谱质心近似、全带 RMS —— 但必须如实说明它不是频谱。**

| 特征 | 怎么算 | 诚实边界 |
|---|---|---|
| 全带 RMS | 逐样本 `v²` 累加，最后开方 | 与 v2.9.0 逐值一致（单测对齐） |
| **低频带** | 一阶低通 `state += a(v−state)`，`a = 1−exp(−2π·150/fs)` | 与 v2.9.0 的低频节拍通道**同一条递推**（常量直接引用，不复制） |
| **中频带** | `LP(2k) − LP(150)`（带通） | 一阶只有 −6 dB/oct，泄漏大：60Hz 信号在中频带上仍剩 **37%** |
| **高频带** | `x − LP(2k)`（高通） | 同上 |
| **频谱质心** | 三个频带代表频率（75/1k/6k）的幅度加权平均，再按 `ln` 映射到 `[50Hz, 16kHz] → [0,1]` | **不得报 Hz**：代表频率是约定值；分辨率只有 3 个频带 |
| **瞬态** | 低频/全带两条并列判据（见问题 2） | 时间分辨率受缓冲粒度限制（见问题 2 的实测） |

**结构证据（它是"无 FFT"这件事的可执行判据）**：`low + mid + high == x` **逐样本精确成立**
（单测覆盖）—— 任何分帧 + 窗函数的方案都不满足它。**没有分帧、没有窗函数、没有频域变换、没有 PCM 环。**

**代价**【实测】：S6 上 4096 帧立体声一次 `process` = **574 µs**，**162 倍实时**余量。

**明确不做**：真 FFT（铁律 28 未翻案）、`android.media.audiofx.Visualizer`（需 RECORD_AUDIO、
8-bit FFT、capture size 必须 2 的幂；调研的 7 个开源播放器**零采用**）、
任何会被读成频谱的视觉（`spectrumColoring` 仍恒为 false）。

## 问题 2：瞬态检测方案？

**答：音频线程每缓冲判定；缓冲内部每 10ms 结算一次；判据 = 「相对慢速基线的增量」∧「超过衰减的峰值记忆」∧「不在冷却窗口内」，低频带与全带两条并列。**

### 2.1 真机实测的缓冲粒度改变了设计【实测】

| 设备 | 采样率 | 平均帧数 | 平均时长 | 回调率 |
|---|---|---|---|---|
| S6（Android 7.0） | 44100 / 48000 | 4410 / 4800 | **100.00 ms** | 11.0 Hz |
| PCL110（Android 16） | 44100 / 48000 | 4410 / 4800 | **100.00 ms** | 11.5 Hz |

⇒ `TeeAudioProcessor` 原样透传解码器的块，粒度是**运行时行为**，比 v2.9.0 注释假定的粗得多。
两条后果：

1. **所有时间基准必须现算**（`帧数 ÷ 声道数 ÷ 采样率`）；基线系数按 `dt` 现算
   （固定步长会让 τ 从 0.8s 漂到 3.5s）；
2. **判据不能只按"一个缓冲一次"结算**：10ms 的击打落在 100ms 缓冲里，
   整缓冲 RMS 会被稀释 √10 ≈ 3.2 倍 —— 幅度 0.4 的击打在整缓冲下只有 0.081（低于 0.10 门槛）漏检，
   子帧下有 0.247（判出）。⇒ `SUB_FRAME_MS = 10`，每样本只多两次加法。

### 2.2 判据的四个部件（**【事实】** + **【实测】**）

| 部件 | 解决什么 | 参数 |
|---|---|---|
| 相对慢速基线的增量（绝对 + 相对） | 绝对门槛跨曲目不可用 | `0.05` / `0.35`（与 `WaveformEffectsState` 同值） |
| **衰减的峰值记忆** | 衰减尾巴被**重复判定** | τ = 250ms、比值 1.6 |
| 冷却窗口（毫秒） | 一次击打只出一个瞬态 | 90ms（v2.9.0 的 180 会把 180 BPM 的八分音符合并） |
| 低频 + 全带两条并列 | 前者抓底鼓/贝斯，后者抓军鼓/拍手/高频击打 | — |

**判据的演化有实测记录**：冷却 180 → 21 次（尾巴重复判定）；「等包络落回谷底」→ 21 次；
「要求包络在上升」→ 21 次（被逐缓冲 RMS 的相位起伏骗到）；峰值记忆（只低频带）→ 22 次；
**峰值记忆（低频 + 全带各一份）→ 16 次 = 期望值**。

### 2.3 与 v2.9.0 低频通道的关系：**复用，不是新建**

`low` 就是那条 150Hz 递推（常量直接引用）。新建的只有：全带判据、峰值记忆、按毫秒的冷却、子帧结算。
消费方的切换是**互斥**的（外部信号有效时内置判据整个不跑）⇒ 不存在同一次击打被判两次。

### 2.4 诚实边界

- 冷却是 90ms、峰值记忆把有效最小间隔推到约 117ms ⇒ **快于约 8.5 次/秒的击打会合并**；
- **发布仍是每缓冲一次** ⇒ 视觉对一次击打的反应最多滞后「一个缓冲 + 一帧」≈ **100~133ms**。
  这是数据通路的性质（PCM 每 100ms 才到齐），不是判据的问题；**【未验证】**没有量化实际对齐误差。

## 问题 3：动效绑定逻辑与档位映射？

**答：五个动效各自绑定到一个明确的音频特征；档位决定「这一档有哪些」，独立开关决定「用户留不留这一项」。**

| 动效 | 音频特征 | 触发 / 映射 |
|---|---|---|
| 冲击波 | **瞬态** | 触发一次 + 幅度随击打力度（0.55..1） |
| 光晕 | **瞬态** | 同源；精致 1 圈、炫技 2 圈（起始进度错开） |
| 粒子 | **中频 + 高频能量** | 生成速率与能量线性正相关，低于门槛**恒为 0** |
| 波形频带响应 | 低/中/高频（**逐柱**占比） | 每根柱子按那一刻的占比决定实心低沉色 or 流动明亮色；炫技档 + 三条频带能量条 |
| 背景呼吸 | **全带 RMS** | 响度包络 → 背景 alpha/scale |

**档位映射**（唯一落点 `MotionEffects.of`，纯函数、单测逐格断言）：

| 档 | 内容 |
|---|---|
| 简洁 | 波形基础 + 背景模糊 + 背景呼吸 |
| 精致（默认） | + 冲击波 / 光晕（1 圈）/ 粒子（低密度 10/s）/ 频带响应（逐柱着色）+ B 档 |
| 炫技 | + 粒子高密度（26/s）/ 光晕 2 圈 / 频带能量条 + C 档（封面 3D） |

**独立开关**（铁律 26）：`motion_shockwave` / `motion_halo` / `motion_particles` /
`motion_wave_bands` / `motion_breathing`，**默认全开**。
「独立」由单测逐项证伪：关掉任意一项**只**影响那一项。

**铁律 25 的可执行判据**：静音输入下所有随时间变化的量必须收敛到**精确的 0**，
且收敛后不再排帧（`MotionBindingsTest.静音输入下所有随时间变化的量都收敛到零`
—— 这条用例在实现过程中真的抓出了一个缺陷：响度包络没有吸附阈值 ⇒ 帧时钟永不空转）。

**铁律 23 的变更（用户明确要求）**：**自动降级机制整个删除**，渲染只由「档位 + 总开关 + 逐项开关」决定。
`MotionEffects` 上不再有水位字段、`MotionPrefs` 上不再有推进入口（两条反射断言）。

## 问题 4：性能预算与降级策略？

**答：音频线程 162 倍实时余量；帧路径精致档 ≤28 笔新增绘制、炫技档 ≤49 笔；自动降级已取消，兜底改为「初始档位 + 逐项开关 + 每个动效自身的硬上界」。**

| 项 | 数字 | 来源 |
|---|---|---|
| 音频线程（S6，4096 帧立体声） | 574 µs / 次，**162× 实时** | 【实测】`PROBE-FEATURE-COST` |
| 每样本 flop | ≈8（v2.9.0）→ **≈17**（v3.0.0） | 【估算】代码算式 |
| 音频线程分配 | **0** | 【事实】状态在 `configure` 时分配一次 |
| 精致档每帧新增绘制 | ≤1 实心渐晕 + ≤1 描边圆 + ≤26 实心圆（逐柱着色 **0 笔新增**） | 【估算】池容量 × 稳态存活数 |
| 炫技档每帧新增绘制 | ≤2 + ≤4 + ≤40 + 3 条能量条 | 同上 |
| 帧率上限 | API<26 或低内存 ⇒ 30fps，否则 60fps（**未改**） | 【事实】`visualizerFrameIntervalMs` |

**降级阶梯**：**没了**。原四级阶梯（砍 B → 砍 A → 波形降档 → 改写 `motion_tier`）已删除，
理由与替代手段见 `probe-motion-binding.md` §7 与 `probe-perf-budget.md` §3。

**本版最大的性能风险**：【未验证】取消自动降级之后，**S6 在炫技档下是否仍然可用**。
v2.9.0 的阶梯曾把 S6 的动效砍掉过，现在不砍了 —— 帧时间数据是唯一判据（见 `../verification/`）。

## 探针阶段的三条可复现结论（抄给下一个改这里的人）

1. **缓冲粒度必须实测**：它是 100ms（11 Hz），不是"几十 Hz"。任何假设固定粒度的判据都会在真机上失效。
2. **时间常数必须按 dt 现算**：固定步长在 100ms 粒度下会把 0.8s 的基线变成 3.5s。
3. **「关掉开关 = 零开销」现在是两个开关**：可视化与"界面动效要不要特征"分开，
   两者都关时音频线程只剩两次 volatile 读。
