# 网易云取链超时：地址族根因与客户端修法（v3.8.1）

来源：2026-10-30 同设备对照实验（原始报告 `RESULTS.md`，本文件只记录**结论 + 落地改动**）。

## 一、根因（实测，不是推断）

失败发生在 **TLS 之前**：

1. DNS 按系统顺序先返回一个 IPv6 地址（例：`2409:8c6a:b021:1400:0:4:0:3`），其后才是 IPv4（`117.135.207.67`）；
2. 到该 IPv6 地址的 TCP 握手**没有任何回包**；
3. 单地址 `connectTimeout = 30s` 远大于调用整体截止（实验里 8s），于是调用在尝试 IPv4 之前被取消。

指纹：`ttfb = -1`、耗时≈截止值（8001–8003ms）、日志里没有任何 TLS/HTTP 事件。

### 四段对照（同一曲、同一冻结登录态、显示顺序轮换）

| 条件 | 只读请求 | 可播响应 |
|---|---:|---:|
| 系统 DNS 顺序，单地址连接等待 30s | 12 | **0** |
| 仅 IPv4 | 12 | **12** |
| 系统顺序 + 连接阶段压到 **2s** | 12 | **12** |
| 恢复原参数（反向确认） | 2 | **0** |

第三行是关键：**保留 IPv6**、只把单地址连接等待收短，IPv6 超时后同一 Call 内改连 IPv4 即成功（2154ms 协商 h2，2312ms 拿到可播地址）。

包级旁证：90 秒 wlan0 TCP 头观察里 14 个 IPv6 SYN/重传**无一回包**，同时收到 2 个 IPv4 SYN-ACK。

## 二、本次没有证明的事（保持边界）

- 没有把故障归到某运营商路由器或网易云 IPv6 节点（缺两端抓包）。
- **没有重现**历史的 `REFUSED_STREAM` / `CANCEL`；那条独立的流级根因仍然成立，不能混为一谈。
- 2 秒只是单变量实验值，**没有**直接写进生产配置。

## 三、客户端改动（v3.8.1）

### 1. `AddressPreference`（新增，`network/AddressPreference.kt`）

- `order(list)`：**IPv4 前置、IPv6 保底**；纯 IPv6 环境原样返回（不砍可达性）。
- `ipv4First`：OkHttp `Dns` 实现，挂在 `RetrofitClient.baseClient` 上 —— 所有派生客户端（含取链、歌词、封面、预热、HTTP/1.1 回退）自动继承。

### 2. 单地址连接预算 30s → 8s（`RetrofitClient.baseClient`）

让"首个地址无响应"能在调用截止前把机会让给下一个地址。`readTimeout` 保持 30s（大响应体不受影响）。

### 3. 为什么不改成 2s / 不全局禁 IPv6

- 2s 是实验值；移动网络首次连接（含 DNS 之外的路由建立）常常 >2s，太激进会把好网络也判死。
- 全局禁 IPv6 会让纯 IPv6 环境直接不可用，且报告明确要求不做这件事。
- 若要进一步优化，方向是**有界地址竞速**（并行发起、先到先用），需要单独回归慢网/代理/用户取消。

## 四、验证

- `AddressPreferenceTest`（4 例）：IPv6 前置被重排、多 IPv4 保序、纯 IPv6 不变、空列表不变。
- 全仓单测 3447 项全绿；两模拟器（API 33/34）安装 3.8.1 后取链、一起听、扫描均正常。
- 真机复测口径：同一网络下播放一首 jymaster 曲目，看 `NcrustHttpTiming` 的 `ttfb` 是否不再是 -1、耗时是否回到百毫秒级。
