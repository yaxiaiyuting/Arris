# Ncrust v2.4.0-gpl 更新说明（用户可读）

## 这一版解决什么问题

搜索「周杰伦」→ 进艺人主页 → 专辑列表是 ncm 的，点进去**播不了**；
你得自己发现「哦，得切到 qm」，然后再搜一遍。

原因不是 bug，是**以前压根没做跨源聚合**：艺人页、专辑页、单曲页都只认 ncm 一个源。

v2.4.0 把这三个页面改成**双源聚合 + 版权可用性优先**。

## 你会看到的变化

### 1. 三个页面都能同时看到两个音源

- **艺人主页**：专辑列表、单曲列表同时来自 ncm 与 qm，每一行都标着它来自哪个源。
- **专辑页**：曲目列表两源合并，能播的排前面。
- **单曲页**：同一首歌两源都有时并列展示，**默认选能播的那一源**。

### 2. 不再默认 ncm，默认「能播的那一个」

以周杰伦为例：ncm 这边探测下来一首能播的都没有，qm 有。
页面会直接默认到 qm，并告诉你为什么：

> 此源（netease）本次探测没有可播放曲目，已默认切到 qqmusic

你仍然可以手动切「双源 / 只看 ncm / 只看 qm」。

### 3. 版权状态如实标注，不猜

- 确认能播 → 「可播放」
- 需要会员 → 「VIP」
- 服务端明确说没有版权 → 「此源无版权」
- **判不出来 → 什么都不标**

最后一条是刻意的：这一版宁可留白，也不给你一个可能错的结论。
qm 那边我们不会标「无版权」——因为它的接口里根本没有能证明这件事的字段
（实测 97 首歌的 `action.switch` 全部是同值，零区分度）。

### 4. 匹配不确定时，分开展示

跨源匹配是**推断**，不是事实：两个平台之间没有任何共同的身份编号（没有 ISRC、没有指纹）。
所以每一对合并都有置信度，并且你能看到依据：

> 匹配：完全一致 · 依据：曲名 + 艺人 + 时长差 0ms + 版本标记一致

置信度不够的，**两侧各显示一行**，绝不硬凑成一对。
——这一版的新铁律就是「**匹配不准时宁可分开展示，也不能给错专辑 / 错单曲**」。

## 实测依据

- 艺人跨源匹配：11 位艺人样本，**11/11** 达到可合并置信度（完全一致 8 / 高度一致 3）。
- 专辑跨源匹配：48 对样本，**48/48** 达到可合并置信度（其中 15 对需要名称归一化才配上）。
- 单曲跨源匹配：230 首样本，完全一致 123 / 高度一致 61 / 可能一致 46 / 无法匹配 26。
- 版权判定与「服务端到底给不给音频文件」的 A/B 对照：ncm 侧 **假阳性 0、假阴性 0**。

细节见 `PROBE-SUMMARY.md`。

## 已知限制（如实）

1. 探针全部在**匿名态**完成（本机真机无法读取登录态）。登录后能播的曲目只会**更多**，
   所以「默认切源」的判断在登录态下会比文档里的数字更乐观。
2. **不做简繁归一**：`周杰伦` 与 `周杰倫` 在本版视为两个艺人（宁可不合并，也不冒错配风险）。
3. **艺人页不逐张专辑探测版权**（44 张专辑 × 2 源 = 88 次请求，页面会不可用）。
   艺人页的默认源由该艺人**曲目列表**的可播放比例决定；单张专辑的精确判定在专辑页做。
4. qm 侧不标「可播放」以外的版权结论（没有可用字段）。

## 升级影响

- 新增一个本地文件 `ncrust_match_cache`（匹配结果缓存，7 天有效，最多 400 条）。
- **其余所有本地数据一个字节未动**：收藏、歌单、本地歌单、歌词缓存、离线缓存、播放队列
  都会原样保留。
