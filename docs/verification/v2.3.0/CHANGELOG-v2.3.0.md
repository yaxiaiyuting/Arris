# Ncrust v2.3.0-gpl

> 一个第三方 ncm / qm Android 客户端（GPLv3 fork）。
> 本版是**库界面重构 + 本地歌单 + 音源与版权标注 + 横屏歌词自动居中**。
> 探针先行：五个探针问题的实测答案见 `docs/verification/v2.3.0/PROBE-SUMMARY.md`。

---

## 一、你可以用到的变化

### 1. 库界面：QQ 歌单一步可达，分类顺序改成「单曲 / 歌单 / 专辑」

「库 → 歌单」现在一页里按音源分成三块，**互不合并**：

- **本地歌单**（新，见下）
- **ncm** —— 新建入口 + 云端歌单
- **qm** —— **歌单直接平铺在这一页**，不再需要先点一个入口行再进二级页面

空状态分两种说清楚：「登录 qm 后可查看歌单」／「暂无歌单」。
另外，一个音源在转圈或报错**不会**再挡住另一个音源。

### 2. 本地歌单：可以自己攒一张歌单，而且**删掉的歌不会自己回来**

- 任意歌曲长按 → 「加入本地歌单」（与「加入歌单」并排）；
- QQ 歌单详情页有「转存为本地歌单」——把一张远程歌单变成可编辑的本地副本，并立刻同步一次；
- 本地歌单详情页：**下拉刷新** / 右上角刷新 / 每首「从歌单移除」/ 「清空歌单」/ 「删除歌单」。

它遵守一条规矩：**只加不减**。

| 你做的事 | 结果 |
|---|---|
| 手动删掉一首 | 这一首从列表消失，**之后同步不会把它加回来** |
| 远程歌单新增了歌 | 同步时**追加到末尾** |
| 远程歌单删了歌 | 你本地那一首**保留** |
| 手动加的歌 | **永远保留**，同步不会动它 |
| 手动重新加回删过的那首 | 恢复，并且**清除「删过」的记录**（位置不变） |
| 清空歌单 | 列表与「删过」的记录**一起清掉**（确认框里明确写了后果） |

> 「清空」与「删除」的差别写在确认框里：清空之后已删除的歌会在下次同步时回来，
> 删除则是把这张歌单整个去掉。这是本地歌单最容易让人困惑的一点，所以我们没有藏起来。

### 3. 搜索 / 艺人 / 单曲：一眼看出**哪首歌能播、用哪个源**

- **每一行都标音源**（ncm / qm）。以前只有 QQ 标，聚合列表里分不清谁是谁。
- **能确证的才标**：`可播放` / `需会员` / `无版权` 三个小角标。
  判不出来的行**一个角标都不显示** —— 我们不会在搜索阶段就假装某首歌能播。
- **原唱 / 翻唱**角标（ncm）；翻唱且接口给了原曲信息时，副标题补「原唱：<艺人> · <曲名>」。
  QQ 侧没有等价字段，所以**不打任何版本标签**（宁可不说，也不说错）。
- 点播放却放不出来时，会提示「此源无版权，可切另一源：<另一个音源>」。
  **不会自动帮你换源** —— 那需要在失败路径里发网络请求猜歌，风险大于收益。

### 4. 横屏歌词：5 秒不碰屏幕，自己回到正中

- 横屏（大屏模式 / 平板两栏）下，当前行**居中**显示（竖屏保持原来的偏上位置，一个像素没动）；
- 你把歌词上下拖走之后，**5 秒不碰屏幕**就会平滑地滑回当前行；
- 手指按着的时候**不会**被打断 —— 松手后重新开始计时；
- 顺带修掉一个老问题：**暂停时拖走歌词，它以前会永远留在那儿**（详见「修了什么」）。

## 二、修了什么

### P0 · 横屏歌词「手动调整后留在原地」

真机复现（暂停态，当前行全程同一句，屏幕用三连拍 md5 相同证明静止）：

| 时刻 | 当前行高度（占面板） |
|---|---|
| 滑动前（自动位置） | 0.36 |
| 滑动后 +1.64s | 0.76 |
| 静置 +8.57s | 0.76（**不变**） |
| 静置 +20.61s | 0.76（**不变**，截图与上一张逐字节相同） |

**根因**：5 秒超时那段代码只放下「别跟着我」的旗子，**没有滚动**；
真正把歌词拉回去的是「换行」那条路径 —— 所以暂停 / 间奏 / 长句时它永远不会回正。
播放时因为每 2~3 秒就换一行，这个 bug 被掩盖了。

### 顺带发现并修掉的另外两个问题

1. **release 包里 R8 把本地歌单的落盘字段名混淆成了单字母**
   （`{"a":"netease","b":"local:…"}`）。同一个包里读写自洽所以不崩，
   但下一次构建的混淆映射一变，老数据就一条都读不出来 ⇒ 本地歌单会静默消失。
   已加 keep 规则，并补了 4 条断言「落盘 key 名」的回归单测。

2. **搜索行的角标被省略号吃掉**：第一版把角标接在副标题末尾，
   长专辑名（如 `The Life of a Showgirl: The Encore`）会把「可播放 / 原唱」整段截掉 ——
   而那恰恰是你唯一需要一眼看到的信息。角标已移到**歌名同一行**。

## 三、已知问题与未验证的部分（如实）

1. **搜索周杰伦的中文关键词未在真机上跑过**：`adb shell input text` 只支持 ASCII，
   本机没有可用的 ADB 中文输入法。真机用的是 `Taylor Swift`；
   判定逻辑与关键词无关，中文场景的字段证据来自探针的原始响应。
2. **「无版权」角标没有真机截图**：它只在约 0.3% 的行上出现（整池 591 条里 2 条），
   本轮搜索结果里没撞上。判定逻辑有单测（含两条反向断言）。
3. **「翻唱」角标 + 「原唱：X · Y」副标题没有真机截图**：同上，本轮结果里没有翻唱版本。
4. **本地歌单的「远程同步」四条规则（规则 1~4）没有在真机上跑**：
   需要一张绑定远程来源的本地歌单，入口已做好（QQ 歌单详情页「转存为本地歌单」），
   但验证进行到一半时手机从 USB 掉线，未能恢复。这四条规则有 7 条单测覆盖。
   真机上跑通的是规则 5 / 6 / 7 + tombstone 重启持久化 + 清空。
5. **横屏「触碰重置 5 秒计时」与「拖拽中不打断」没有端到端时序数据**：
   adb 无法在手指按住的状态下暂停测量；这两项只有单测覆盖。
6. **竖屏没有做「滑走 + 静置」的对照试验**：探针只在横屏做了决定性复现。
   从代码看该现象与方向无关（同一份歌词面板），但这是推理，不是实测。
7. **平板宽屏布局没有截图**：那台设备被系统密码锁屏挡住，无法自动化操作。
   宽屏的播放器两栏布局代码路径与上一版相同（本版只改了传给歌词面板的一个参数）。
8. **没有在超低端设备 / Android 8 以下重测**：本版只在 Android 7.0（SM-G9209）
   与 Android 12（WGR-W09）上装过 release 包。低端机的 dex 指标未重新测量。
9. **未做压力测试**：本地歌单的容量上限（单表 2000 条 / 100 张）是设计值，
   没有测过写满之后的 prefs 文件大小与读取耗时。

## 四、合规与边界（本版没有做的事）

- **不做远程歌单写操作**：本地歌单只写本机存储，依赖里没有任何远程写接口。
- **不做跨源歌单合并**：两个平台的歌单各自独立展示。
- **不接第三个音源**。
- **不碰华为控制中心卡片**。
- **没有改包名、没有冒用身份、没有蹭别家会话标识**。
- **没有移动任何已发布的 tag**。

## 五、技术备注（给下一个改这些代码的人）

1. **`Strings` 的构造参数上限是 245，不是 AGENTS.md 里写的「余量 ~9」。**
   真实算式：`this(1) + N + ceil(N/32) + DefaultConstructorMarker(1) <= 255`。
   N=245 刚好用满，N=246 会让类加载抛
   `ClassFormatError: Too many arguments in method signature`（真机表现为启动即崩）。
   本版为此把两条离线文案搬进 `OfflineStrings` 腾位置，并补了
   `StringsConstructorBudgetTest` 把这条钉死。
2. **判据全部来自实测，不是文档推断**：
   `privilege.pl > 0` ⇒ 可播放（30/30、假阳性 0）；
   `privilege.st == -1` **不可用**（30 首里 15 可播 / 15 不可播）；
   `originCoverType ∈ {1,2}` 的原唱/翻唱自洽率 96.7%（60 条抽查）。
3. **凡是落盘/落网的结构，字段名与泛型签名都是对外契约**，不能交给 R8 决定。
