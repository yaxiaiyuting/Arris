## 一、小球「落地好快 + 像平移到下一帧 + 没有后续弹性碰撞」

你后来确认的那句「**就是粘在顶上一起平移，短线也是，一点都不真实**」说得完全准确 —— 我查下去发现是**三处**问题叠在一起，没有一处是"参数没调好"。

### ① 小球被焊死在柱顶上

旧代码在"静止在地面上"那一支里**无条件** `位置 = 地面; 速度 = 0` —— 柱子怎么动，小球就怎么平移。

物理上柱顶只能**推**小球、不能**拉**它：地面下落得比自由落体快时，小球必须留在原处开始下落。现在多了「脱离地面」这一支：

```
地面上升得够快  ⇒ 被顶起（弹起来）
地面下落得够快  ⇒ 脱离，走自由落体   ← 本次补上
地面几乎不动    ⇒ 被托着走（保住"能停住 / 不空烧帧"两条契约）
```

### ② 碰撞时机错了：在"穿进地面之后把位置夹回来" —— 这会**凭空给小球补能量**

每帧补 `½·g·穿透深度`，而每跳只损失 `e²`，于是存在一个**稳定极限环**：小球在柱顶上**永远微跳、永不停止**。实测该停在 0.4，实际 600 帧都还在 `0.4006 ± 0.006` 之间循环。

旧参数（e=0.45）只是**刚好**把这个环压到"看不见"的阈值以下才没暴露 —— 也就是说"能停住"一直是靠调参数凑出来的，不是算法保证的。

现在改成解析求出**接触时刻**，碰撞发生在地面**上**，就没有瞬移、也不再有额外能量。顺带两个好处：

- 轨迹对帧时间**精确** —— 实测 30 / 60 / 90 / 120 / 146Hz 分别在 52 / 103 / 154 / 205 / 250 帧静止，物理时长都是 **~1.72 秒**（真正与刷新率无关）；
- 能不能停住由"反弹顶点是否低于阈值"这条真判据决定，与 `e` 取值解耦。

### ③ 参数按正确的口径重标定

旧的 `g = 32` 是按「满幅 1.0 落到 0 用 250ms」反解的 —— 但**那个口径测错了对象**：小球日常只有一个顶点（0.2）的行程，按 32 算只有 **112ms ≈ 6.7 帧**，一帧走 4.6% 的画幅，肉眼读到的就是"跳了一下"。

现在按**顶点行程的滞空时间**定标：

| | 改前 | 改后 |
|---|---|---|
| 重力 `g` | 32 | **10**（顶点 0.2 的上升段 112ms → **200ms**） |
| 恢复系数 `e` | 0.45 | **0.7** |
| 后继顶点（从 0.2 起跳） | 0.040 / 0.008 / 0.0016 | 0.098 / 0.048 / 0.024 / 0.011 / 0.006 |
| **看得见的弹跳次数**（按 2% 满幅的感知门槛） | **1 次** | **3 次** |
| 整串收敛时间 | ~0.45s | **~0.82s** |

你定的**顶点 0.2 没有改**，单测仍然断言"实测顶点 = 0.2"。

### ④ 短横：从"小球的影子"改成真正的**峰值保持**

它自己的代码注释一直写着它是「**这一格曾经到过的最高点**」，但实现是 `小球位置 + 固定偏移` —— 所以它和小球**永远同步移动**，只是一条被抬高的影子。这正是你说的"它和小短线是一样的"。

现在补上那份状态：短横记住这一格到过的最高点，并按 **0.5/秒**缓慢回落（满幅回落用 2 秒 ≈ 20 根柱）。于是两者终于各说各的话 —— **小球在下面弹，短横压着它到过的最高处慢慢下来**；小球弹回接近最高点时，由既有的错开量兜住不重叠。

## 二、竖屏「很容易顶满」

全链唯一的显示增益是三泳道的 `[2.6, 3.5, 6.6]`（低/中/高），它让**高频带在输入 0.152 就饱和**，而实测高频 RMS 的 p95 = 0.137、max = 0.228 —— 也就是**高峰必然撞到 1.0**，柱顶与它上面的光点/短横一起贴死在画布上沿。所以"顶满"是常态，不是极端情况。

新增一个**振幅余量 0.88**，只作用于"归一化值 → 像素振幅"这一步（4 处），`centerY`、曲线控制点、横向几何仍用满幅 —— 不动归一化值域（`[0,1]` 仍是硬契约）、不动物理、不动泳道增益标定、不动背景带高度。

取值依据：最坏情况（小球顶到 1.0、短横再抬 `2×光点半径 + 短横厚度`）在 120dp 的竖屏背景带上要求 `f ≤ 0.91`，取 0.88 留出约 7dp 余量。

## 三、音质标签旁显示**实际播放码率**

你要的「音质旁边加一个音频播放码率的数值」。

- 取链侧本来就解析了码率（单位 bit/s），只是**一直只进诊断日志**；现在复用「实际在播音质」那条既有链路推给 UI，没有新造平行状态。换歌、整链取链失败、离线缓存兜底三处一律置 0。
- **拿不到就不显示**，绝不显示 `0kbps` —— 那串字符会被当成一次测量结果读，写一个假的比不写更糟。走这条的路径不少：离线缓存、B 站音频区、取链失败、不带码率字段的老缓存条目。
- **向下取整而不是四舍五入**：判据里 `≥ 1,400,000` 才算高解析，而 1,399,600 四舍五入会写成 `1400kbps` —— 数字看起来够到高解析、标签却写「无损」，同一行自相矛盾。整除写成 `1399kbps` 就一致了。
- 码率排在「档位名 → 状态角标」**之后**：宽度不够时最后声明的先被省略号挤掉，而「已降级 / 无权限 / 该曲无此档位」那几个诚实角标不能被一个可选的数字挤掉。
- **`Strings` 与 8 个语言文件一个字节未动**（数字 + 单位不需要翻译）。

### 附带修掉的一个既有缺陷：B 站把**文件字节数**当码率

B 站音频区那条响应里的 `size` 是**文件字节数**（实测 `10374528` = 一个 10MB 的 m4a），旧代码却把它读成 bit/s ⇒ 界面会显示 `10374kbps`，档位判定里还会被读成「5 Mbps 以上的母带级文件」。

那条响应里确实**没有码率字段**，所以如实填「未知」。影响面已核：它的容器默认是 `m4a`，而档位判定只认 `mp4/flac/mp3` ⇒ 旧值对**档位角标无影响**，只是会显示一个假数字；B 站 DASH 那条路用的是真带宽，不受影响。

## 未验证项（如实记录）

1. **观感只能在真机上看**：小球弹跳、短横保持、振幅余量这三条都是**观感**改动，本版**没有真机 / 截图验证** —— 只跑了编译与 JVM 单测。物理量（滞空时间、反弹次数、顶点高度、与刷新率无关）都有单测钉住，但"好不好看"必须你自己看。
2. **横屏波形条的短横仍可能越出上沿**：32~56dp 的窄带按同一条余量公式要求 `f ≤ 0.86 / 0.76`，而本次取 0.88（为 120dp 的竖屏背景带定的）。彻底不越界要上 `clipToBounds`，属于另一个改动，本次没做。
3. **宽屏控制条的音质片宽度预算没调**：加上码率后，窄条（平板竖屏 352dp）尾部可能被省略号截掉。没有调大那个常量 —— 调大会让「手机竖屏 360dp 也放得下」的既有单测翻红，等于用"整个音质片不挂"换"少截几个字"。真机看一眼再定。
4. **QQ 音源会显示"档位定义值"**（如 `320kbps`），那是档位名本身就等于码率，不是实测；FLAC 档位返回 0 ⇒ 不显示。
5. B 站音频区的码率一律不显示（响应里确实没有这个字段）。
