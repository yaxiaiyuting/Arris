## 一、你报的问题

> 「qq 音乐登陆身份在一周左右就会掉，重新登录很麻烦，尝试解决」

这个问题的答案不是「腾讯的票据不稳定」，而是**这个客户端从来没有续过期**。

### 根因（有本机落盘样本，不是推断）

翻出你手机上的 `ncrust_qq_prefs.xml`，那份 cookie 只有 **5 个字段**：

```
uin / qqmusic_uin / qqmusic_key / qm_keyst / psrf_musickey_createtime
```

而 qm 在你登录时下发的响应里还有 `refreshKey` / `refreshToken` / `accessToken` /
`openid` / `loginType` / `keyExpiresIn` / `needRefreshKeyIn` —— **一个字节都没存下来**。
全仓库检索「调用 `Login` 且 `loginMode != 1` 的代码」，命中 **0**。

于是票据一到期，客户端手里没有任何能换新票的东西，唯一的出路就是让你重新扫码/重新收短信。
**这不是「一周掉一次」的偶然，是必然**：丢掉续期凭证等于把「可续期的会话」
降级成「一次性票据」。（`psrf_musickey_createtime=1790277358` = 2026-09-24，与「一周左右」同量级。）

## 二、本版怎么做

用同一个端点、同一个方法，只把 `loginMode` 从 `1`（登录）换成 **`2`（刷新）**，
参数带上整份凭证 —— 换来一张新票。触发时机有两条，缺一不可：

| 路径 | 什么时候发生 | 你会感觉到什么 |
|---|---|---|
| **主动** | 冷启动时票据寿命剩不到 **12 小时** | **什么都不会感觉到**（后台静默换票） |
| **被动** | 取链被服务端拒绝时兜底一次 | 极端情况下会有一次短暂的「重新取链」 |

第二条是兜底，覆盖「票据寿命未知的老凭证」「App 挂在后台跨过了整个到期窗口」这些情况。

**从此以后：票据到期会自己续，不需要你再登录。**

## 三、新增：**「QQ 音乐 App 扫码」**登录（扫码这条路现在也能续期了）

你接着问「有办法做扫码的续签吗，还是必须手机号」——**可以，但要换一条扫码路**。

原来的扫码（QQ 互联，手机 QQ 扫）最后一步是交给网页让腾讯自己去换票据，
拿到的**只有 cookie** —— 而 cookie 里没有 `refreshKey`，也没有 `openid`，
所以那条路**结构上不可续期**，到期仍然要重登一次。

新增的这条路是**直接用手机上的 QQ 音乐 App 扫**：

- 手机上装 QQ 音乐 App 就能扫（不用 QQ）；
- 扫完确认后，服务端把凭据推给我们，我们再换一次，拿到的是**完整凭证 JSON** ——
  也就是**能续期的那份**；
- 因此它和手机号登录一样，**到期自动续，不用重登**。

设置 → 音源账号 → qm，未登录时会多一行入口。**默认登录方式没有改**，
原来那两条（QQ 互联扫码、网页登录）都在，你按需选。

### 四条登录路各自到期会不会掉

| 登录方式 | 到期后 |
|---|---|
| 手机号验证码 | ✅ 自动续期 |
| **QQ 音乐 App 扫码**（新增） | ✅ 自动续期 |
| QQ 互联扫码（手机 QQ 扫） | ❌ 需要重新登录一次 |
| 网页登录 | ❌ 需要重新登录一次 |

后两条不是没做完，而是**客户端拿不到续期所需的事实**（只有 cookie）。
所以界面上没有把它们说成「可续期」—— 那会让你选错，然后以为修了没用。

## 四、升级后你该看到什么

| 你的情况 | 升级后 |
|---|---|
| 现在已登录、且是**旧版本登录的** | 与之前**完全一样**，票据到期仍需重登**一次** |
| 重登一次之后（手机号或 App 扫码） | 之后每次到期都静默续期，**不用再重登** |
| 现在就换用「QQ 音乐 App 扫码」 | 立刻进入可续期状态 |
| 登出 / 换账号 | 续期凭证与 cookie 一起清、一起换，不会串号 |

第一条要说清楚：**老登录态里没有续期凭证，这一版也变不出来** ——
那份凭证只有登录的那一刻服务端会给。所以升级后需要**重新登录一次**，
之后才进入「不掉了」的状态。

## 五、合规与隐私（没有变化）

- 只用**你自己登录时服务端下发的凭证**换新票，不采集密码、不代管账号、不绕过任何鉴权；
- 续期凭证与 cookie 一样**只存在本机**（同一个 `ncrust_qq_prefs`），不上传任何服务器；
- 新增的网络出口只有两个，都是腾讯自己的登录端点（取二维码、换凭证），
  没有任何第三条链路。

## 六、已知的未验证项（如实写）

本版有几个「做不到自动化」的地方，写在这里免得你以为是「已经验过了」：

1. **续期的成功路径没有在真机上跑过** —— 那需要一份真实账号的长期凭证，
   开发环境没有 qm 账号。协议链路（端点、参数、码表）有成熟实现的源码依据，
   但没有本仓库的成功态样本。
2. **扫码那三步（真手机扫码 → 收到凭据 → 换凭证）没有跑过** ——
   自动化不可能扫屏幕上的码。已验证的是**握手与订阅全部成功**
   （WebSocket 连接、服务端重定向跟随、CONNECT 与 SUBSCRIBE 被接受），连测 3 次全绿。
3. 所以：**如果你升级后重登一次，一周后仍然掉登录，请把 logcat 里的
   `QqTokenRefresher` 那几行发我** —— 那说明续期请求本身被服务端拒了，
   是这份代码需要修的下一个东西。
