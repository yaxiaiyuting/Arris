# Arris 4.0.0 计划（跳过 3.9.x）

> 版本号：主线 **4.0.0**，`versionCode = 200`（3.8.x 线用满 120–199 后正式跨代）。
> 参考项目：NeriPlayer（音理，GPLv3；歌词库为 Apache-2.0），调研报告见
> `~/deepseek/arris/refs/NeriPlayer-分析.md`。

## 四条工作流（都进 4.0.0）

| # | 工作流 | 目标 | 成本 | 依赖 |
|---|---|---|---|---|
| ① | **歌词核心库移植** | 引入音节级 karaoke 模型 + TTML / 网易 yrc / **酷狗 KRC** / Lyricify / EnhancedLRC 五种解析器 | S | — |
| ② | **歌词 UI 移植** | `KaraokeLyricsView`（逐字渐变/双语/日文间距/呼吸点）替换自研渲染，material3 换成 Kanesumi 组件 | M | ①、④(Kotlin 2 的 Compose 编译器) |
| ③ | **均衡器 / 音效** | 系统 `AudioEffect` 挂到 ExoPlayer audio session；自绘 EQ 曲线 + 预设；设置持久化 | M–L | — |
| ④ | **工具链升级** | Kotlin 2.x + Compose 编译器插件；media3 **1.6.1 → 1.10.1** | L | — |

## 执行顺序

1. **④-a Kotlin 2.x 迁移**（一切的地基：②③ 都要新编译器/新库）
2. **④-b media3 1.10.1**（拿一年半的播放器修复；1.10 需要 Kotlin 2 元数据）
3. **① 歌词核心**（纯 JVM 逻辑，可单测，不动 UI）
4. **② 歌词 UI**（在 ① 的模型上重做渲染层）
5. **③ 均衡器**（独立功能，最后做，风险隔离）
6. 文档/官网/发布：README、CHANGELOG、官网更新记录与卡片、`Arris-v4.0.0-gpl.apk`

## 验收标准

- 每个阶段结束：`assembleRelease` 通过 + 全量单测 0 失败
- ①：五种格式各有一条"真实样本 → 解析成音节"的单测
- ②：旧渲染保留开关（设置 → 歌词 →「逐字渲染引擎」），出问题可一键回退
- ③：EQ 开关默认关闭；关闭时音频链路零改动（避免引入爆音/无声回归）
- ④：Kotlin 2 + media3 1.10 后，3.8.x 的全部播放修复仍生效（含 media3 1.6 的 `isLoading` 断言、OkHttp 数据源、缓存）
