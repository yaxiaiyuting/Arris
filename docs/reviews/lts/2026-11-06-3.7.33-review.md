# Arris LTS 3.7.33 首轮审阅

应用基线为发布标签 `v3.7.33-gpl` 对应的 `0ba4602bd347ad8eeeb7c786d00dcd781625ffb7`，官网发布列表快照为 `d211a7a0f9ee5a031f6725542a6e2f5edae8c4bb`。审阅使用独立的 detached worktree。探针只读本地代码、发布列表和正式 APK，证据分为发布数据重放、纯逻辑复现及静态调用链。没有设备运行、在线请求、真实账户或云端写入。应用代码与发布产物均未改动。

## LTS01 · P1 · 3.7.32 应用内检查漏掉 3.7.33

- **触发与影响** — 从 3.7.32 检查更新，发布列表里的目标资产名为 `Arris-v3.7.33-lts-gpl.apk`。应用会略过该资产并可能提示「已是最新」。官网手动下载可正常使用。
- **调用链** — [ForkRelease.kt:57](../../../app/src/main/java/com/takahashirinta/ncrust/update/ForkRelease.kt#L57) 的正则要求版本号之后紧跟 `-gpl`。[UpdateChecker.kt:142](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateChecker.kt#L142) 对解析失败的资产直接继续。[ReleaseFeed.kt:66](../../../app/src/main/java/com/takahashirinta/ncrust/update/ReleaseFeed.kt#L66) 把无候选转为 `UpToDate`，[UpdateService.kt:518](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateService.kt#L518) 把该值当作成功结果结束查找。官网 Worker 在 `d211a7a:relay/src/index.mjs:431–451` 保留资产名称，仅重写下载地址。两代 LTS 的更新模块源码一致。
- **证据** — 将含 118 条发布记录的官网归档交给生产 `evaluateReleases`，3.7.32 得到 `UpToDate`。对照组只把资产的 `name` 改为 `Arris-v3.7.33-gpl.apk`，URL、ID、字节数和 tag 都保持一致，立即得到 `Found(3.7.33)`。属于发布数据的离线生产选择入口复现。[JVM 输出](probes/2026-11-06/jvm.txt)
- **修复方向** — 对已安装旧版本，先由发布列表提供它能识别的资产名，保留现有 APK 及可下载地址。新客户端和发布校验同时兼容现有 LTS 命名，并用真实 Release 快照验证「上一版客户端能找到本版」。
- **与旧结论的关系** — 上次发布验收确认官网和 GitHub 可下载，且更新列表含 3.7.33。实际客户端选择结果以本项重放为准。此项发生在资产名解析阶段，与 I10 已修的同一 Release 逐资产筛选是两个环节。

## LTS02 · P2 · Android 7 的网易云收藏 EAPI 兜底依赖 API 26

- **触发与影响** — Android 7.0/7.1 上，收藏或取消收藏走完 XEAPI、WEAPI 且均未被确认，EAPI 兜底收到非空正文时，编码步骤会解析 API 26 才有的 `java.util.Base64`。服务器可能已收到写入，客户端无法读取业务确认。库的入口把异常收为同步失败并记录日志，用户的本地收藏状态可能与云端不一致。
- **调用链** — [PlaylistApi.kt:986](../../../app/src/main/java/com/takahashirinta/ncrust/network/PlaylistApi.kt#L986) 依次走三个通道，[:1116](../../../app/src/main/java/com/takahashirinta/ncrust/network/PlaylistApi.kt#L1116) 发出最后一次请求，[:1130](../../../app/src/main/java/com/takahashirinta/ncrust/network/PlaylistApi.kt#L1130) 在请求异常捕获之外对原始字节做 Base64 编码。[EapiCrypto.kt:30](../../../app/src/main/java/com/takahashirinta/ncrust/network/crypto/EapiCrypto.kt#L30) 再用同一 API 解码。[LibraryManager.kt:317](../../../app/src/main/java/com/takahashirinta/ncrust/library/LibraryManager.kt#L317) 捕获 Throwable 后以 `false` 结束该意图。
- **证据** — Android SDK 本地 API 索引把 Base64 及 Encoder/Decoder 的引入版本标为 26。正式签名 APK 的 DEX 仍引用这些类型，Lint 历史基线也已有对应告警。[正式包字节码证据](probes/2026-11-06/api24.txt) 这是产物与静态调用链确认，未执行收藏写入，也未测量服务端各通道的失败率。3.7.33 已修的 `ValueAnimator.areAnimatorsEnabled()` 是另一条调用。
- **修复方向** — 让 EAPI 解密直接接收 HTTP 原始字节，删掉这次编码再解码；核对是否仍有字符串解码调用者。用合成响应在 API 24/25 覆盖二进制 AES 正文、明文 JSON 和空正文。

## LTS03 · P2 · 冷启动恢复旧更新时绕过 LTS 通道筛选

- **触发与影响** — 保留曾经发现的主线更新记录后覆盖安装 LTS。例如 4.0.13 缓存 4.0.14 的提示，再在 Android 10 或以上以更高 `versionCode` 覆盖安装 LTS 3.7.33。冷启动可恢复主线提示并提供下载。3.7.33 的 code 215 高于 4.0.14 的 214，下载后该组合仍会被版本校验拒绝。
- **调用链** — [UpdateService.kt:236](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateService.kt#L236) 从共用偏好文件读出旧候选，[:595](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateService.kt#L595) 恢复完整元数据。[UpdateRecovery.kt:21](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateRecovery.kt#L21) 只比较显示版本。[UpdateChecker.kt:75](../../../app/src/main/java/com/takahashirinta/ncrust/update/UpdateChecker.kt#L75) 的通道门控只用于新检查，[ApkVerification.kt:56](../../../app/src/main/java/com/takahashirinta/ncrust/update/ApkVerification.kt#L56) 到下载完成才拒绝低 code。
- **证据** — 同一 4.0.14 候选对当前 3.7.33 的新鲜通道检查返回 false，恢复函数保留该候选。属纯逻辑复现，偏好载入与更新页传播由静态调用链核对。[JVM 输出](probes/2026-11-06/jvm.txt)
- **修复方向** — 冷启动用同一套规则复核候选的版本线、构建变体与版本。丢弃旧通道缓存时同步取消对应的检查 TTL，允许立即检查当前通道。

## LTS04 · P2 · 普通歌词在小幅向后拖动后可继续显示下一句

- **触发与影响** — 正常播放、未缓冲时，经底部进度条短距离向后拖动，落点跨回上一句，但回退不到 1 秒。例如从 10.2 秒拖到 9.5 秒，句界在 10 秒。音频已回到上一句，普通歌词仍可停在后一句，直至音频再次跨过该句界。点歌词行直接 seek 有本地对齐，现象针对进度条这条入口。
- **调用链** — [PlayerCardExpanded.kt:342](../../../app/src/main/java/com/takahashirinta/ncrust/ui/player/PlayerCardExpanded.kt#L342) 直接调用 [PlayerViewModel.kt:3288](../../../app/src/main/java/com/takahashirinta/ncrust/ui/viewmodel/PlayerViewModel.kt#L3288) 更新位置；普通歌词的 [LyricsView.kt:304](../../../app/src/main/java/com/takahashirinta/ncrust/ui/player/LyricsView.kt#L304) 只从位置流识别偏差，正常播放且差值不超过 1.5 秒时不立即重置显示。随后 [LyricClock.kt:58](../../../app/src/main/java/com/takahashirinta/ncrust/lyric/LyricClock.kt#L58) 把不足 1 秒的回退当作采样抖动。跟唱还有单独的 320ms 判据，本项聚焦普通歌词。
- **证据** — 生产时钟与面板二分函数将 9500ms 映射为上一行，但显示时钟仍保留 10200ms，对应后一行。JVM 只验证时钟和行选择，进度条接线由源码确认。v3.7.32 的旧循环已存在同类阈值限制。[JVM 输出](probes/2026-11-06/jvm.txt)
- **修复方向** — 让播放器位置流显式携带 seek/discontinuity 信号，或让进度条和歌词点击共用即时重锚入口。显式跳转允许回退，小幅正常采样漂移仍按原有规则过滤。

## LTS05 · P3 · 跟唱页「切换主行」有按钮但回调为空

- **触发与影响** — 打开含译文的歌曲并进入独立跟唱，顶部原文/译文按钮可点，主副行位置和按钮文案都不会变。3.7.32 也有相同接线。
- **证据** — [KaraokeScreen.kt:382](../../../app/src/main/java/com/takahashirinta/ncrust/ui/player/KaraokeScreen.kt#L382) 在有译文时展示按钮，[:387](../../../app/src/main/java/com/takahashirinta/ncrust/ui/player/KaraokeScreen.kt#L387) 把它接到 `toggleLanguage`。[PlayerCardExpanded.kt:250](../../../app/src/main/java/com/takahashirinta/ncrust/ui/player/PlayerCardExpanded.kt#L250) 以全局的译文显示布尔值初始化主行，并传入空 lambda。属静态调用链确认。
- **修复方向** — 绑定独立的跟唱主行状态和点击处理，用现有显示设置作初值；对无对应译文的句子回落原文，检查原文、译文两次点击及切换歌曲后的状态。
